整理日期：2026-09-10。

本文用于后续逐项查看桌宠行为。结论来自当前源码检查和仓库内旧代码副本、设计文档对照，未启动桌宠逐项实测。此目录无法读取 Git 历史，因此旧代码副本不能确认为最早提交。本文是现状记录，不代表新增功能已经安排开发。

**更新：举牌已接入真实行为与大模型决策。模型可额外返回 message 留言，最多24字、保留30分钟，可单独留言而不冒泡。独立放在桌面的便签仍是规划。**

本次留言改动已通过48项相关测试、类型检查、构建及隔离Electron实窗验证。牌面采用奶油纸色、深棕描边、圆角与微软雅黑，位置上移避免角色头部遮字。留言保存在当前进程中，页面重载可恢复，应用重启不保留；不属于定时提醒。

## 2. 已实现行为的具体边界

### 2.1 冒泡与动作

- 大模型可以选择当前角色的可用动作并生成台词，也可以决定不行动。
- 主动聊天支持 1～3 条短台词。
- 动作是否可播取决于当前角色实际拥有的素材，不能把动作名称视为所有角色都具备的能力。
- 相关代码：[大模型行为组装](../app/src/main/brain-llm.ts)、[聊天规则](../app/src/main/pet-chat-rules.ts)、[行为执行器](../app/src/main/behavior-executor.ts)、[角色播放器](../app/src/renderer/pet/player.ts)。

### 2.2 举牌

**手动举牌可用。** 右键菜单提供“举牌…”；已有手动牌时提供“换个牌子…”和“收牌”。输入文字上限为 60 字。

**自动状态牌可用。** 显示优先级为：手动牌 → 有效留言 → 一次性提示 → agent 工作状态 → 会议状态 → 音乐状态。对应监听必须能获取到状态，才能自动显示。

**规则脚本举牌已补通。** sign 分支通过独立留言状态发布到renderer，默认30分钟后收起；sign(null)或右键“收牌 / 收起留言”立即清除。普通行为打断不会清除留言。重复同一句不会重置到期时间；角色切换时不会显示其他角色的留言。

举牌是跟随角色显示的牌面，不等同于在桌面某处留下独立便签；当前手动牌记录也不是持久化便签存档。

相关代码：[右键菜单](../app/src/main/ipc.ts)、[牌面记录](../app/src/main/local-sign.ts)、[牌面显示与输入](../app/src/renderer/pet/local-main.ts)、[木牌组件](../app/src/renderer/pet/signboard.ts)。

### 2.3 走动与拖拽

- 播放 walk 动作时会实际移动桌宠窗口，不只是原地踏步。
- 当前固定向左走，单次最多 280 像素，接近屏幕边缘时减少位移或只播放动画。
- 需要当前角色有可播放的 walk 素材。
- 尚不支持通过通用 move 指令指定目标坐标，也没有自由寻路能力。
- 用户拖拽是独立交互，不能等同于大模型自主移动。

相关代码：[桌面移动和拖拽](../app/src/renderer/pet/local-main.ts)、[状态机](../app/src/renderer/pet/state-machine.ts)。

### 2.4 叽歪声

本地 Speaker 已实现台词配合合成音效，可控制声音开关和音量。这不表示每一条大模型气泡都会自动读出，也不等同于自然语言语音朗读。

相关代码：[说话编排](../app/src/renderer/pet/voice/speak.ts)、[声音合成](../app/src/renderer/pet/voice/synth.ts)。

### 2.5 花园互动

已实现播种、施肥、收获、繁育，以及相关土地菜单和结果卡。播种或收获成功后，桌宠会临时移到对应地块旁播放动作，再回到原位；拖动、隐藏、换角色等会取消表演。

garden_sow / garden_harvest 专用素材缺失时会使用已有动作回退，不能将回退表演当作专用素材已生成。当前花园操作主要由用户界面触发，大模型尚未获得自主播种、施肥、收获的操作接口；珍稀收获事件可以触发大模型评论。

相关代码：[花园窗口与表演](../app/src/main/garden/windows.ts)、[花园交互](../app/src/main/garden/interaction.ts)。功能说明见 [花园 demo 文档](garden-demo.md)。

### 2.6 联机与旧版串门

当前存在公共房间成员桌宠显示、状态与牌面同步代码。这和旧版“双角色自动串门聊天表演”是不同路径。

旧版 VisitOrchestrator 保留了双角色同屏切换聊天动作、定时结束的逻辑，但本次源码搜索没有找到 startVisit 的实际启动调用，因此暂列为“保留代码，入口未确认接通”。

相关代码：[房间桌宠显示](../app/src/main/rooms/room-pet-display.ts)、[房间桌宠渲染](../app/src/renderer/pet/room-pet-main.ts)、[旧串门编排器](../app/src/renderer/pet/visit.ts)。

## 3. 大模型目前能自主调用什么

当前自动脑把模型输出组装成 play、say 和 sign 三种步骤。message 是可选的短留言，强调“希望用户稍后也能看到”，区别于随口说话。自动脑可以只留言；主动聊天仍需回答用户，可额外留言。模型上下文包含当前留言，提示避免重复与频繁替换。

| 能力 | 是否已接入模型主动输出 |
|---|---|
| 选择可用动作 | 是 |
| 生成冒泡台词 | 是 |
| 决定不行动 | 是，自动脑支持 |
| 留言、替换留言 | 是，message 字段；不直接覆盖手动牌 |
| 提前收起留言 | 用户右键操作；模型空字段保留旧留言 |
| 指定坐标移动 | 否 |
| 留便签、定时提醒 | 否 |
| 颁奖、写可见日记 | 否 |
| 自主操作花园 | 否 |

补充：如果模型选择的动作恰好是 walk，播放器的现有逻辑会带动窗口位移。这是播放动作附带的效果，不是模型获得了任意移动能力。

## 4. 行为指令的实现状态

源码中的类型定义比执行器的真实能力更宽，看到指令名称并不代表功能已经实现。

| 指令 | 含义 | 执行器现状 |
|---|---|---|
| play | 播放动作 | 已实现 |
| say | 显示台词 | 已实现 |
| sign | 留言或收起留言 | 已实现，独立于动作队列保留30分钟 |
| wait | 等待一段时间 | 已实现，用于编排，不是独立可见行为 |
| move | 移动到坐标 | 跳过，未实现 |
| note | 留便签 | 跳过，未实现 |
| award | 颁奖 | 跳过，未实现 |
| journal | 写日记 | 跳过，未实现 |

内部日志另外会记录模型 thought，这不代表 journal 指令已经可用。

相关代码：[行为类型与校验](../app/src/shared/behavior-dsl.ts)、[实际执行分支](../app/src/main/behavior-executor.ts)。
