# 表情待机指令与白色稳定性修复（2026-09-19）

## 实测原因

小白白的 `.job/idle_request.json`（2026-09-19 23:17）使用「自娱自乐」第 0 秒作为参考，视频 prompt 却包含原待机素材的「扭呀扭；扭呀扭」。导入将名称、含义和标签拼进 `motionDesc`，场景绑定复制该字段，管线又按用户生成覆盖项读取。

本地现有文件白色区域抽样：参考 PNG 为 RGB 255/255/255，生成首帧约 247/248/246，原始视频约 241/240/233，原 WebM 约 240/239/232。视频首段偏紫、随后偏黄，循环存在色温跳变。主要偏差在模型生成阶段，抠像/编码只引入少量额外差异；主体 alpha 为 255。形态变异在首帧及原 MP4 中已存在，不是抠像产生。

## 修复边界

- 新导入/修改表情名称不再写生成 `motionDesc`，语义继续存在素材条目和资源标注中。
- `generationMotionDesc` 适配旧记录：与素材名称/含义/标签拼接完全一致的字段不覆盖默认动作。显式保存标记 `motionDescSource: user`，即使与标签同文也保留。完整 prompt 覆盖仍优先。生成请求与编辑预览使用同一适配。
- 重命名素材前清除各别名及生成变体上已知的旧标签，防止名称改变后无法识别遗留字段；未知手写内容保留。
- 原样提示词补充角色自身填色、曝光与首尾颜色一致的约束。
- 原样模式基础动作抠像时检查本次参考快照：仅透明、有黑色线条且有大量纯白填色的近黑白图启用白色恢复。彩色填充、灰色平涂、奶油色主体、无透明背景等均跳过。颜色/灰色小区域检测有采样阈值，不是完整的语义分割。
- 恢复在去绿边之后、归一化之前，RGB 192 以下不动，192–224 平滑提亮，224 以上固定纯白；alpha 不变。原有 chromakey、环带去绿参数和禁止全图去绿规则不改。此处理只针对符合条件素材的白色漂移，不能修复形态，也不承诺消除所有边缘变化。
- 新任务在动作状态记录 `colorCorrection: reference-white`。不自动请求付费生图或视频。
