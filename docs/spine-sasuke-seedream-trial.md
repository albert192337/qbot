# 佐助 Seedream 实测

2026-10-11。用户指定改用 Seedream 测试，不能使用会话 imagegen 代替。

## 第一步：目标图

- 模型：实际响应 `doubao-seedream-5.0-lite`，经项目 `pipeline/dist/ark.js` 的 Seedream 分支调用；使用当前本机 Ark 配置，未复制或记录密钥。
- 输入：佐助少年经典装束的文字描述；现有鸣人目标图仅作绘画风格及骨架比例参考。没有用户上传的佐助参考图，因此此轮不能证明上传身份图的还原能力。
- 输出：`output/spine-lab/sasuke-seedream/target-v1.png`，2048×2048。一次 HTTP 请求成功，约 37.2 秒，无重试。
- 服务返回 usage：1 张图，output_tokens/total_tokens 各 16384；这是图片服务用量，不可直接按文本 token 价格换算。
- 地址为 `/api/plan/v3`。没有取得货币实扣，不能把公开按量价当作本次账单。
- 人工参与：助手选参考、写提示词、看图判断。用户随后确认目标图，文件哈希记录于 `approval.json`。

目标图保留黑色尖发/侧刘海、木叶护额、蓝色高领短袖、浅色短裤和绑带凉鞋。角色完整、微侧朝向、纯色胶囊眼、无固定嘴。生成的背景为白色；后续部件透明处理必须单独验证，不能用这张图证明原生透明能力。

## 部件与装配结果

实际追加两次 Seedream 部件图请求，分别 56.8 秒、50.6 秒，各返回一张图。这里的“拆图”是模型重新绘制分离部件，再由本地程序去背景、切割、打包，不是模型直接返回可用 Spine 文件。

- 第一版：头和单腿可用，但躯干仍带袖子，一侧手臂缺上袖；背景含渐变和分格线。
- 第二版：无袖躯干可用，但头发失去侧刘海，每个腿格都画了双腿，不能整张采用。
- 最终人工选第一版头/腿、第二版躯干，镜像完整手臂补另一侧；调整色键阈值、模板初始位置和眼睛位置。详见 `assembly-selection.json`，不能算全自动通过。
- 本地沿用短颈、规则躯干网格、独立袖网格和双骨权重。短袖袖口仍宽而僵硬，衣服轮廓与目标有差异，作为实验结果保留，未达到自动交付质量。

预览：`http://127.0.0.1:24361/?skin=sasuke&expressions=1&v=1`。点击动作和表情标签可播放，23 类动态眼形复用现有程序，未逐个生图。正式创建 UI、上传身份图验证及 39 状态语义映射仍未完成。

## 验证与成本

- 178 个骨骼动作数值检查无异常；七个动作各四帧抽查，包含跑步、睡觉、抬手。不是 178 个动作全部视觉验收。
- 23 个表情、529 次表情切换测试无报错，输出 `output/spine-lab/sasuke-expressions/`；动作抽帧 `sasuke-final/`。
- 总计 3 次图片请求／3 张图，模型请求等待合计 144.6 秒，不含本地处理和人工返工。
- 每次服务返回 generated_images=1、output_tokens=total_tokens=16384；没有另外调用付费视觉复核模型。不能按文本 token 价格计这些图片 token。
- `/api/plan/v3` 未返回人民币实扣，`chargedCNY=null`。公开按量单价只是预算参考，不能代替本次套餐账单；人工返工成本未计量。

结论：Seedream 能生成可识别的佐助目标图；部件一致性和完整性仍不稳定。本次得到可播放实验包，依赖人工辅助，不证明自动创建链路跑通。

执行脚本 `scripts/trial-sasuke-seedream.mjs` 支持 target / parts / parts2；已有结果直接复用，部件阶段检查目标审批哈希，存在未完成请求记录时拒绝自动重试，防止误重复付费。脱敏请求与提示词均在 `output/spine-lab/sasuke-seedream/`，汇总为 `trial-summary.json`。本地选件处理脚本 `scripts/prepare-sasuke-trial.py`；打包后必须依次运行 `calibrate-naruto-mesh.cjs sasuke`、`calibrate-spine-sleeves.cjs sasuke`。
