# P0 Launch Implementation Plan

> **For agentic workers:** Implement in this session, task-by-task. Preserve existing desktop, market and room behavior. Never commit credentials.

**Goal:** Invited nontechnical users can create a character without model keys, recover generation, and play immediately on either desktop platform.

**Architecture:** A separate Node generation service owns credentials and durable jobs, sharing the compiled Electron-free pipeline. A main-process cloud client downloads allowlisted assets and mirrors snapshots into existing character/task views. Local generation remains an advanced option. Companion rewards and a first-run guide use existing progress and room APIs.

**Tech Stack:** TypeScript, Node HTTP, filesystem atomic JSON, Electron IPC, Vitest, nginx and systemd.

## 1. Hosted generation
- [x] Add `generation/server.mjs`, `generation/service.mjs`, `generation/store.mjs` and mock HTTP tests. Bearer invite hashes authenticate a bounded private beta; credits reserve atomically with idempotent client UUIDs. Limit uploads, job counts, retries and worker concurrency. No arbitrary upstream URLs or credential-bearing responses.
- [x] Persist queue and job metadata; release workers while waiting for candidate confirmation. Restart resumes queued work. Only serve source/candidate/action/manifest allowlisted files owned by the authenticated invite.
- [x] Wire `pipeline/src/stages.ts` concurrency and preserve saved video IDs on retry so temporary failures do not resubmit successful video jobs.

## 2. Desktop integration
- [x] Add `app/src/main/cloud-generation.ts`, IPC and types for invite enrollment, status, create, pick and retry. Store bearer token in a mode-0600 main-process file. Normalize source images before upload. Downloads are atomic; preserve locally edited manifests on repeat polling.
- [x] Route cloud task operations through existing hatch bridge and start recovery polling on application startup. Display queue, connection and retry errors; advanced local mode continues to support user keys.
- [x] Update hatch UI with cloud/local selection, quota display and explicit image-upload consent; keep failed jobs on their task screen.

## 3. First play
- [x] Give a one-time starter reward to new and existing profiles using a persisted grant version; add platform-independent companion points paired with earned boxes. Preserve inventory, add atomic save/backup and cap box accumulation.
- [x] Add home guide: interact with pet, open a first box, enter own room and create a character. Dismissal persists; first boot opens the guide. Avoid requiring Claude Code or observation permissions.
- [x] Add tests for migration idempotency, reward cadence and cap behavior.

## 4. Validation and deployment
- [x] Run generation HTTP tests, pipeline and app tests, typecheck and production builds. Add app checks to Windows CI and a Mac build workflow.
- [x] Inspect remote target, deploy a separate service under `/opt/qbot-generation`, data under `/var/lib/qbot-generation`, root-only environment under `/etc/qbot-generation.env`, route `https://albertbeta.cn/qbot-generation/`. Keep existing TLS and sites. Record rollback and operational commands without secrets.
- [x] Run authenticated health/quota and real generation smoke; distinguish API authentication from completed asset generation. Verify packaged Mac startup and visible UI; record Windows/signing limits honestly.
