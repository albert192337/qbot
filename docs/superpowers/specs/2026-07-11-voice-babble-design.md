# QBot 叽歪语音模块设计（气泡文案 + 程序化语音 + 语音包）

> 版本：v1.0（2026-07-11）
> 上游文档：`DESIGN.md`（产品全案）、`2026-07-11-mvp-pipeline-and-pet-client-design.md`（第一切片）
> 本 spec 范围：桌宠随机自言自语的完整链路——气泡文案库 → 叽歪语音合成 → 语音包体系 → 设置项。

---

## 0. 背景：本轮需求的整体拆分

本轮头脑风暴涉及 4 个子系统，按依赖关系拆分为独立的 spec → plan → 实现循环，本文档只覆盖第 1 个：

| 序 | 子系统 | 状态 |
|---|---|---|
| 1 | **叽歪语音**（本 spec） | 已设计 |
| 2 | 桌面串门 + 双人互动标签系统（本地角色概率触发、动画标注双人适用与左右站位） | 待设计 |
| 3 | 小房间窗体（点击展开的房子场景：走动、家具交互、社交；画风参考代号鸢心纸君房间） | 待设计，依赖 2 的双人标签系统 |
| 4 | 联机模块（房间码创建/加入、选形象、聊天、聊天内容匹配动作表情） | 待设计，依赖 1+2+3 |

## 1. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 技术路线 | 纯 WebAudio 程序化合成（逐字映射 + 韵律层），零音频资产、零 API 成本、完全离线 |
| 淘汰路线 | TTS + 卡通化后处理（试听判定"不够可爱"，念字感是底色，天花板低） |
| 内容关联方式 | 逐字确定性映射：同一个汉字永远同一个音，句子有可辨识的"声音轮廓" |
| 范围 | 气泡文本系统与语音一起做（语音依附于气泡文案，"和内容关联"才有载体） |
| 触发时机 | 仅 idle 随机自言自语（交互反应、事件台词后置） |
| 文案来源 | 手写种子库 30~50 句（LLM 离线批量生成后置） |
| 角色声线 | 按角色 id 自动分配语音包 + 包内微调，写入 manifest 持久化 |
| 语音包 | v1 内置 3 个：软萌圆润 / 活泼蹦跳 / 奶音颤颤（试听全部通过） |
| 设置项 | 语音开关 + 音量滑条 + 说话频率三档，默认开 |

## 2. 定位与复用契约

语音引擎唯一入口：

```ts
speak(text: string, mood: Mood, voice: VoiceParams): Promise<void>  // resolve 于播放结束或被打断
```

未来串门对话（子系统 2）、小房间社交（3）、联机聊天表情（4）全部复用这个入口，只是 text/mood 的来源不同。本切片内唯一的调用方是 idle 自言自语调度器。

## 3. 气泡文案库

### 数据格式

`app/src/shared/utterances.json`，随 app 打包：

```json
{
  "version": 1,
  "utterances": [
    { "id": "idle-001", "text": "今天也要加油哦！", "mood": "happy", "scenes": ["idle"], "weight": 1 }
  ]
}
```

- `mood`: `happy | sleepy | neutral | curious | annoyed`——驱动语音韵律与可选的动作联动
- `scenes`: 本期只有 `idle`；字段保留，之后串门/深夜等场景直接加条目，不改代码
- `weight`: 抽取权重，默认 1
- 种子库规模 30~50 句，五种 mood 均有覆盖，句长控制在 4~14 字（过长叽歪声会腻）

### 触发与调度

- 并入现有自主行为调度器（`state-machine.ts` 的随机行为循环）：idle 期间按"说话频率"设置的随机间隔触发一次自言自语
- 抽取规则：按 scene 过滤 → 按 weight 加权随机 → 不与上一句重复
- **动作联动**：mood 匹配现有 talk 动作时说话期间切过去（happy→`talk_happy`，annoyed→`talk_annoyed`），说完回 idle；其他 mood 在当前动作上直接冒泡
- **打断**：拖拽开始（mousedown+move）立即打断——气泡消失、语音停止、动作按现有拖拽逻辑走；正在说话时不触发新的自言自语

### 气泡 UI

- 桌宠窗口内、角色头顶的圆角气泡（DOM 元素，非独立窗口），随窗口移动
- 显示时长 = 语音时长 + 1 秒，结尾 200ms 淡出；语音时长一律取自 `plan()` 的调度总长，因此语音开关关闭时气泡时长不变
- 文字超长自动换行，气泡最大宽度约窗口的 80%

## 4. 语音合成引擎

### 分层

1. **逐字映射层（内容关联）**：每个汉字按字符码确定性映射到元音共振峰（a/i/u/e/o 五组 F1/F2）+ 音高偏移。标点不发声，只影响韵律。
2. **韵律层（可爱灵动）**：由语音包参数决定基础音色与节奏，再叠加通用规则：
   - 疑问句（`？`结尾）：末两字音高上扬（×1.12 / ×1.26）
   - 感叹句（`！``～`结尾）：句尾追加两声上挑小花腔
   - mood=happy：节拍 ×0.85（加速）；mood=sleepy：节拍 ×1.2（放慢变软）
   - 每音节起音带向上小滑音（起音 ×0.85 快速滑至目标音高，"鸟啼感"）

### 纯函数规划 + 播放器分离

```ts
plan(text, mood, params): Blip[]        // Blip = { t, f0, vowel, dur }，确定性纯函数
play(blips, volume): Promise<void>      // WebAudio 调度：三角波+高八度泛音 → 双 bandpass 共振峰 → lowpass → gain 包络
```

- `plan()` 可单测，不需要发声；`play()` 只做调度，逻辑极薄
- 全部在渲染进程内完成，无主进程音频参与
- P2 增强（本期不做）：字符码映射升级为拼音声母/韵母映射，逐字辨识度更高

## 5. 语音包体系

- 一个语音包 = 一组纯数据参数：波形、基础音高、节拍步长、颤音开关、旋律模式（是否按五声音阶蹦跳）、共振峰 Q、泛音混合比等。**加新包 = 在 `packs.ts` 加一条常量，不改引擎代码。**
- v1 内置 3 包（参数以试听 demo 调校值为起点）：

| 包 id | 名称 | 特征 |
|---|---|---|
| `soft` | 软萌圆润 | 基频 ~400Hz，平稳节奏，无颤音，无旋律 |
| `bouncy` | 活泼蹦跳 | 基频 ~430Hz，五声音阶旋律，长短交替节拍 |
| `baby` | 奶音颤颤 | 基频 ~520Hz，7Hz 颤音，音节滑音连接 |

### 按角色分配

- 角色首次加载时若 manifest 无 `voice` 字段：按角色 id 哈希分配 `pack`，并在包内做微调采样（`pitchScale` ∈ [0.85, 1.15]，`rateScale` ∈ [0.9, 1.1]，同样由哈希确定），写回 manifest（懒迁移）：

```json
"voice": { "pack": "bouncy", "pitchScale": 1.08, "rateScale": 0.95 }
```

- 同一角色声音永远稳定；不同角色即使同包也听得出区别
- `pipelineVersion` 不变（字段增补向后兼容，旧客户端忽略未知字段）

## 6. 设置项

设置页新增"语音"区块，存入现有 config（`userData/config.json`）：

| 项 | 形式 | 默认 | 说明 |
|---|---|---|---|
| `voiceEnabled` | 开关 | 开 | 关闭时气泡照常出现，只是不发声 |
| `voiceVolume` | 滑条 0~100 | 70 | 映射 WebAudio 主 gain |
| `talkFrequency` | 安静/正常/话痨 | 正常 | 随机间隔：安静 5~12min、正常 2~6min、话痨 45s~3min |

## 7. 多角色并发

多个角色同时在桌（多个 pet 窗口）时，主进程维护一个**发言锁**（简单 IPC：`voice:acquire / voice:release`）：同一时刻只允许一个角色出声+冒泡，其余角色的自言自语触发直接跳过（不排队）。避免叽歪声重叠成噪音。

## 8. 模块结构

```
app/src/renderer/pet/voice/
├── synth.ts        # plan() 纯函数 + WebAudio 播放器
├── packs.ts        # 3 个语音包参数常量 + 按 id 哈希分配逻辑
└── speak.ts        # 编排：挑文案 → 气泡 → 发言锁 → synth → 动作联动/打断
app/src/shared/utterances.json
```

- `state-machine.ts` 只新增"到点了→调 speak()、拖拽→打断"两个挂钩，说话逻辑不入侵状态机
- `characters.ts`（主进程）负责 voice 字段懒迁移；`ipc.ts` 增发言锁与设置读写

## 9. 测试

| 层 | 方法 |
|---|---|
| `plan()` | 单测：确定性（同输入同输出）；疑问句末两字 f0 上扬；感叹句尾多两个花腔 blip；mood 改变节拍；不同包/不同 pitchScale 产出不同计划 |
| 文案挑选器 | 单测：scene 过滤、weight 加权、不连续重复 |
| voice 字段迁移 | 单测：无字段补写且哈希稳定（同 id 两次加载同参数） |
| 发言锁 | 单测：占用期间第二个请求被拒 |
| 听感验收 | 手动：3 包 × 3 情绪句过一遍；两个同包角色听得出差别；拖拽打断即停 |
| 端到端 | 手动：默认设置下角色 idle 数分钟内冒泡+出声，频率档位切换生效，静音生效 |

## 10. 明确不做（本切片）

- TTS / 真人声路线（已淘汰）
- 拼音声母/韵母精确映射（P2）
- LLM 批量文案生成、交互反应台词、事件台词（深夜催睡等）
- 串门/双人对话语音、联机语音（由后续子系统复用 `speak()` 接口）
- 用户手动选语音包的 UI（分配自动，自定义后置）

## 11. 验收标准

1. 预置角色上桌后，默认设置下 2~6 分钟内至少自言自语一次：气泡 + 叽歪声同步出现，声音与文字节奏对应（字数≈音节数，疑问句尾上扬）
2. happy/annoyed 文案说话时切到对应 talk 动作，说完回 idle
3. 两个不同角色声音明显可区分；同一角色重启后声音不变
4. 拖拽瞬间气泡与声音立即消失
5. 设置三项均实时生效并持久化
6. `plan()` 与文案挑选器单测全绿；运行期零 API 调用、零网络依赖
