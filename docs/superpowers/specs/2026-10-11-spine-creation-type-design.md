# 上传图片创建 Q 版 Spine 角色

日期：2026-10-11。状态：实现前设计草案，待用户确认；并非功能上线记录。

## 目标与已确认基础

用户要求在上传角色图后自主选择生成 Spine 角色，并将鸣人、张起灵、吴邪已经认可的颈肩/双臂修订写入创建流程。沿用 `docs/spine-character-creation-workflow.md` 的目标图先行、版本锁定、动态表情、有限校准及最终预览要求。

目前正式创建只有图片到视频动作的流程；Spine 播放器和两个预置包已经存在。实验装配依赖 Python/Pillow、人工参数和 Electron 页面，尚不是任意参考图的生成服务。本次须实现真实任务分支，不能仅加一个选项或直接返回旧角色换名。

## 方案选择

推荐：在现有创建表单加入独立「角色类型」，共用上传、名字、人设与任务中心，后端按 video/spine 分流。已有视频角色不迁移。

备选一：单独 Spine 创建页。隔离容易，但重复上传/任务/恢复界面，用户需要跳页。

备选二：只开放本地实验入口。开发较短，但默认云端用户不能真正创建，不满足常规创建入口的预期，不作为最终交付。

## 用户流程

1. 上传 PNG/JPG/WebP 并填写名字，可选人设。
2. 选择「视频角色」或「Q版 Spine 角色」。类型与绘画风格分开；Spine 首期限定可适配当前模板的二足人形，动物/物件选视频类型。
3. Spine 说明：固定骨架、实时动作、独立动态表情；先确认形象，再生成角色。提交前显示模型、预计费用、预算上限及上传说明。
4. 根据上传图与实际模板比例生成一张完整目标图，并展示表情方向及标签。用户可以确认或付费换一版；目标更改即使旧确认失效。
5. 确认后生成部件，执行透明处理、识别锚点、装配、有限校准和动态检查。
6. 展示可点击动作/表情的实际 Spine 预览，以及未支持能力；用户确认后完成创建，并沿用已有「放到桌面」操作。
7. 失败停在具体阶段，保留已完成成果。重试只重跑失败阶段；超时且无法判断服务端是否已扣费时标记费用待核对，不能默认为免费失败。

孵化小屋 `app/src/renderer/nursery/create-form.ts` 与控制台 `app/src/renderer/console/panes/hatch.ts` 同步支持，状态恢复后类型不丢失。保留现有视频模式为默认，Spine 由用户主动选择。

## 任务与接入边界

- 增加独立 `creationType: video | spine`，旧任务缺省为 video。贯通 draft、preload/IPC、主进程、云端 marker、服务端持久化、任务快照、恢复/重试和产物同步。
- Spine 状态：target → awaiting_target_confirmation → parts → calibration → validation → awaiting_result_confirmation → done；失败保留失败阶段、已完成产物和诊断，不伪装成视频动作进度。
- 任务记录模板/目标/表情版本哈希、用户确认版本、模型及计费渠道、请求 ID、费用事件、每轮参数、报告与最佳有效候选。
- `pipeline` 内建立独立 Spine 模块，复用现有图像模型适配器和错误处理；不调用视频生成 API。识别服务提供结构化锚点及置信度；低可信度暂停，不回退为另一角色参数。
- 将实验 Python 装配移植或封装为可部署的确定性资产处理模块。服务端必须实际安装并测试所需依赖，不能依赖开发机器临时文件或运行中的 24361 端口。
- 模板资产单独版本化：骨骼、atlas 布局、站姿、动作映射、已验证的躯干/手臂拓扑、许可证及来源；生成包只能含受限数据文件，不含可执行脚本。
- 云端 `generation/service.mjs` 增加类型能力声明和 Spine 分支；客户端提交前检查能力。旧服务不支持时明确不可用，不降级为视频、不扣费创建错误类型。
- 本地和云端共用任务模块。云端产物白名单增加固定目录下 Spine JSON/atlas/PNG、必要预览与报告，保留路径、哈希、大小检查。
- 暂不假定现有生图端点可靠支持透明底。必须能力检测；非透明输出经独立分割/抠图与颜色保真检查，未通过不得打包。付费分割成本单列；初版推荐本地透明处理，无新增模型费用。

## 美术和动态验收

执行主流程 spec 新增的双肩、短颈和弯肘规则。先得到符合模板比例的目标图；部件内不得重复袖子/手/脖子，头部不烘焙眼睛。眼形和头发分层。

有效人形表情为 23 类，04/11 禁用且保留历史 ID。表情板可以由同一实际眼形引擎在目标头图上渲染，避免额外生成 23 张角色图。若模型额外生成独立艺术参考板，计入一张生图。23 个动态表情均须能点击播放，现有 39 状态目录逐项报告显式映射或不支持；不得宣称全部任务特效已完成。

标准动作复用固定骨骼并接已有 22 个语义动作；不能将 178 源动画数说成 178 个已验收功能。全动画检查有限值/附件合法性；七类关键动作四分位检查身份、关节、衣摆、五官与遮挡；保留原画/静态装配/动态对照。

最多三轮几何装配（首次加两次修正）。几何修正不自动生图；素材需要重做时须受任务生图额度约束。差候选不能覆盖最佳有效候选。完成状态与用户结果确认分别记录。

识别/复核预算是工程预留，尚无该新管线 token 实测，不是供应商套餐或承诺单价。实际模型费公式：图片各次实扣之和 + 输入 token×输入价/1e6 + 输出 token×输出价/1e6 + 可选分割费。换图、模型已完成但响应丢失的请求可能增加费用；免费几何重算不应重新生图。

运行总成本还包括渲染算力、存储/带宽、套餐摊销、人工返工和软件固定费用，以上表格均未包含。按量费用与套餐额度分别记账；每次请求保存 usage/请求 ID/单价版本，未知用量不记为 0。目前不能声称“通常成功成本”或稳定成功率，需要至少一批独立新角色实际跑通后统计。

## 实施与验收顺序

1. 创建类型/状态契约、版本和费用记录、既有 video 回归。
2. 模板化装配与袖/躯干网格、图像能力检测、部件识别、离线坏输入测试。
3. 目标确认、Spine pipeline、有限重试和渲染质检、23 类动态表情正式播放器接入。
4. 小屋/控制台 UI 与实际预览；本地任务恢复、云端服务能力及白名单同步。
5. 三历史样例作为回归；至少一个全新上传的人形完成真实 API 端到端试跑，并报告实扣或无法取到实扣的具体部分。已有资产重放不能代替新生成验收。
6. 模型费用调用前展示预计成本；重复提交、恢复、确认重入不重复付费；无效输入/预算耗尽/模型失败/低置信度均不得发布完成包。
7. 类型检查、构建、契约/几何/费用测试、隔离 Electron 创建与加载验收。部署云端后验证能力标识，未部署不得报告线上可用。

本草案尚未修改创建 UI、IPC 或云端服务。用户已认可的校准规则已写入主流程，新的正式创建类型待此设计确认后实施。
