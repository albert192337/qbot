# QBot 总产品规格：多人陪伴、养成追求与社交商业化

版本：v1.0

日期：2026-09-18

状态：产品方向整合稿，供后续模块设计与排期使用；不表示文中功能已实现或数值已经验证。

范围：游戏、陪伴、社交、分享裂变、商业化、基础设置六大模块，以及贯穿它们的体验、经济和交付顺序。

## 1. 产品定位与本轮决定

QBot 是以 AI 角色为情感载体的多人桌面陪伴与轻养成产品。玩家在工作和日常使用电脑时与角色相处，通过种植、天气变异、繁育和制作积累收藏，再带着角色和成果进入朋友的空间，共同做事、展示、回应并建立关系。

**真实多人和完整体验设计是本项目商业化路线的必要前提。** 不能把单机花园、角色生成工具或两只本地角色的自动演出，当作多人产品已经成立。第一轮核心产品验证就必须包含不同玩家之间的真实交互，社交不再是单人功能完成之后才考虑的附加模块。

商业化围绕玩家能感知的审美、稀缺性、收藏深度、身份差异和社交展示展开。随机获取承担期待与惊喜，养成承担投入和积累，多人场景承担价值被看见和被回应。角色生成费用属于工具服务收入，单独核算，不能替代这条游戏商业化路线。

这是本项目选择的战略假设与设计要求，不是“所有产品只有多人才能盈利”的普遍结论，也不代表接入多人后自然会产生收入。

| 模块 | 玩家获得什么 | 对整体产品的贡献 |

## 2. 玩家、动机与核心循环

初始验证人群为愿意在电脑旁长期使用桌宠、喜欢角色或表情包，并愿意与朋友进行轻量互动的玩家。先组织两三个真实玩家的小圈子验证完整来往，同时保留通过开放花园与繁育需求认识陌生人的扩展路径。

| 动机 | 典型选择 | 应获得的反馈 |
| --- | --- | --- |
| 陪伴与角色表达 | 选择角色、人设、动作与互动方式 | 角色像自己喜欢的样子，回应适量，经历被记住 |
| 收集与培育 | 等待天气、挑选亲本、尝试性状组合 | 有可理解的结果、谱系和下一次尝试的方向 |
| 装扮与展示 | 制作家具、布置空间、佩戴珍藏 | 自己看得见变化，来访者能识别并回应 |
| 合作与关系 | 互助、赠礼、一起挂机、共同繁育 | 对具体对象产生记忆，有共同成果与再访理由 |
| 稀缺与身份 | 追求主题珍藏、配饰、特殊展示效果 | 投入产生可辨识的收藏差异，而不只是数字余额 |

核心循环：

**选择个人或共同目标 → 安排种植与日常行动 → 天气、商店或朋友带来机会 → 合作、繁育与制作 → 获得可展示成果 → 被欣赏、回应与记住 → 产生更高目标和新的来往。**

商业化进入玩家已经理解目标、看到差异、知道商品用途的环节；分享发生在角色、成果和共同经历值得传播的环节。

单人状态支持安排、种植和整理，异步机制承接双方错开的时间。独处时仍有事情做，但首轮产品不能只验证独处玩法。

## 3. 体验设计要求

每个重要功能必须写清六件事：谁因为什么进入、做什么选择、谁会受到影响、即时看到什么、留下什么长期结果、为什么还会回来。只有入口和数值变化，不算体验完成。

### 3.1 首次体验：拥有角色，也进入真实关系

1. 玩家选择、导入或创建角色，快速确认外观、名字和基础人设。
2. 通过一次拍拍或换姿势体验直接回应，确认角色能留在日常桌面。
3. 在小屋选择一个可见目标，例如做出一盏灯或布置一个展示角，完成教学种植与制作。
4. 从邀请链接、好友入口或开放会客空间进入另一名真实玩家的小屋，完成一次打招呼、帮助或赠礼。
5. 对方获得可见记录并可回应；双方看到同一件事的结果，选择下一次合作目标。

无人同时在线时，可向明确开放异步访问的真实家园操作，由对方之后接住。没有合适对象时保留待完成入口，不能用本地角色演出来冒充真人，也不阻塞已解锁的基础玩法。

### 3.2 一次日常会话

回到桌面 → 角色简短回应 → 查看成熟植物、天气机会和朋友消息 → 选择一项当前行动 → 安排下一轮生产或共同任务 → 回到工作。

每日内容分为稳定可安排的生产、自选目标、天气与货架变化、朋友带来的异步事项。任务编排避免把所有内容都变成必须清空的红点。

### 3.3 一次可转化为展示价值的合作

朋友展示一株极光性状植物 → 我查看其来源和开放繁育意向 → 选自己的互补亲本并发邀请 → 双方看清成本、资格和分配后确认 → 分别领取子代 → 培育与收集花材 → 制作主题家具或追踪配饰 → 在家园陈列并邀请对方来看。

这条链应同时提供结果揭晓的惊喜、可持续推进的目标，以及双方共有的谱系或纪念。上述极光植物与家具是体验示例，名称与素材尚未定稿。

## 4. 模块一：游戏

### 4.1 特殊天气与变异

目的：让日常出现值得关注的变化，为种植决策、共同观看、收藏和社交话题提供事件。

正式天气事件应有明确作用范围、开始结束时间、适用植物与结算规则。多人在同一空间看到一致的事件状态。桌面背景和前景效果是呈现层，是否显示壁纸效果不影响已符合条件的游戏结算。

流程：天气预告或出现 → 展示可能影响 → 玩家查看并安排植物 → 角色和场景给出反馈 → 在规定结算点生成结果 → 收获界面解释新增性状及来源 → 可收藏、繁育、制作或分享。

设计要求：

- 天气提供特定变异机会或培育方向，具体影响方式在天气模块 spec 中定稿；不默认所有在场植物必定变异。
- 环境纪念标记与可遗传性状分开；哪些性状可传给子代必须在植物详情和繁育预览中一致展示。
- 每株每轮的判定次数有明确上限，不能反复进出房间、切换天气或重载来重抽。
- 正式事件与本地天气测试隔离，开发菜单切天气不产生正式稀有资产。
- 天气应有可再次参与的机会；不以错过一次事件损坏已有植物。
- 普通种植、肥料和天气共同影响变异时，统一算概率及产出，不能分别独立叠加后遗漏经济影响。

### 4.2 繁育与植物追求

目的：将随机收获转成可选择的长期探索，也为玩家之间的互补合作创造需求。

区分两条流程：研究与育苗用于解锁和稳定获得某个物种；亲本繁育用于组合已有植物的可遗传性状。玩家必须能区分“看见配方、完成研究、获得种子、养出成株”。

多人繁育流程：展示愿意合作的植物 → 选择自己的亲本 → 看结果范围、双方成本、资格和产物分配 → 发起邀请 → 对方接受 → 预留双方资产并开始任务 → 一次确定结果 → 双方独立领取 → 保存共同谱系 → 种植与分享成长结果。

本稿建议以双方各得一粒同批次子代作为体验起点，具体为独立基因结果还是相同结果，以及额外产出如何计价，须完成经济模拟后锁定。此提案不直接替换现有本地“两株资格产一粒”的规则。

普通植物需要具备有价值的互补性状；高品质亲本不能成为参与合作的唯一资格。亲本资格消耗、恢复、次数与子代继续繁育能力放入同一预算，避免优秀植物很快失去合作价值，也避免无成本无限复制稀有资产。

邀请在接受前可以撤销、拒绝或过期；接受前不正式扣费，接受时重新校验。接受后的占用、离线、屏蔽、领取和失败补偿必须有确定结果，重试不能重抽。

### 4.3 家具、制作与长期追求

家具作为本稿优先的长期消耗方向：基础功能家具 → 会客与展示组合 → 主题收藏 → 珍藏动态家具；角色高级配饰承担更醒目的个人标志。

首批家具优先具有体验用途：灯改变氛围、茶桌承载双人互动、展示窗台陈列植物、相框保留共同经历。每件家具都应连接获取动机、制作过程、摆放变化和来访反馈。

基础功能空间与必要工作台应能稳定获得。主题外形、动态表现和稀有收藏可形成差异。制作要消耗真实资源；已出售、赠送或投入制作的物品不能继续作为可消耗库存。

是否采用蓝图后制作、成品直得或二者分目录配置，要以玩家能否理解获得内容和完成目标为依据。抽到蓝图时不能演成已获得可使用成品。

### 4.4 3D 地图与 Blender 制作

产品方向：空间逐步转为 Blender 制作的 3D 场景，服务摆放、参观、角色站位、共同活动和成果展示。首个验证场景建议是可会客的小屋与相邻花园，旅行世界地图与城市是否同批转换在场景专项设计中确定。

保留现有 2D 表情包、透明视频角色作为兼容对象，不要求用户重新生成角色。场景需设计接地点、朝向、遮挡、互动位置、可走区域与镜头范围。不能因场景 3D 化，就承诺任意角色有背面、骨骼动作或通用牵手拥抱。

素材交付包括可编辑 Blender 源文件、运行时资产、统一尺寸和枢轴、材质贴图、碰撞或占位、家具交互锚点与版本信息。先用真实多人、不同画风角色和低性能设备验证一个完整空间，再扩大场景数量。

3D 替换不重置已有布置或资产；旧空间到新空间的摆放映射、无法映射物品的收纳与回退在迁移方案中说明。

### 4.5 任务系统与体验编排

任务负责引导、解释、串联和提供选择，而不只是发奖。

| 类型 | 内容 | 完成后的意义 |
| --- | --- | --- |
| 首次引导 | 角色回应、种植、第一件家具、第一次真人来往 | 理解产品完整循环 |
| 章节目标 | 解锁植物、研究、展示、繁育与会客能力 | 获得新的选择和功能 |
| 每日目标 | 订单、安排种植、可选互助 | 短会话也能推进 |
| 事件目标 | 天气观察、当期主题、特殊货架 | 让今天与昨天不同 |
| 共同目标 | 两人培育、共处项目、共同布置 | 留下共同成果与再次联系的理由 |
| 长期目标 | 一件家具、一种植物或一件配饰 | 持续看到缺口和下一步 |

每项任务定义触发条件、前置、完成事件、奖励、演出、有效期和补偿规则。重复领取、断线恢复与跨端同步由同一结算规则处理。主线不要求用户必须抽到稀有结果才能继续。

旅行继续作为主题体验、金币消耗和记忆来源，接入任务和展示；多人旅行与独立旅行资产体系不在首轮默认扩张范围内。

## 5. 模块二：陪伴

### 5.1 和角色直接互动

拍拍、切换姿势、打招呼、拖动、靠近窗口等操作应有清楚的命中区域、响应、结束与恢复。主动操作优先于自动演出，工作和会议状态下的打扰可控。

动作优先用角色实际可用素材与本地规则响应；简单互动不必每次调用模型。没有指定动作时用兼容动作或轻量效果，不能把缺失素材解释成角色真实完成了动作。

### 5.2 表情包的打扰优化

分别控制动作重复、视觉闪烁、气泡频率、声音和遮挡。玩家可停用某个片段、设安静时段、调整主动程度。主动台词、自动动作和用户直接聊天使用不同优先级与预算，避免为了减少说话而让直接互动失去回应。

验收重点为长时间工作中的可接受程度；短时展示“很热闹”不能代替陪伴质量。角色未被回应时可安静结束，不连续索取注意。

### 5.3 人设、记忆与共同经历

人设决定语气、偏好与表达方式；记忆基于实际互动、明确用户信息和真实游戏事件。玩家能查看、纠正、删除或限制主动提及。

增加对真实合作、获赠、共同繁育和纪念的引用。角色可以记住“我们和谁养过这株花”，但私人对话、应用标题、用户画像和本地记忆不随角色包或社交展示默认分享。

手账与朋友圈草稿是内容表达入口。自动生成草稿和向真实玩家发布分开，发布对象和内容由玩家控制。现有本地朋友圈卡不等同于真实社交动态。

### 5.4 UGC 完整流程

导入或生成 → 保留原角色身份 → 检查动作、透明边缘与朝向 → 设置名字和人设 → 预览直接与双人互动 → 上桌或进入家园 → 选择可分享内容 → 他人预览与导入。

原图、封面和动作参考用途分开；分享包不携带凭据、私聊或私人记忆。角色素材有版本、来源与作者标识，错误动作可修正且不破坏旧可用素材。

### 5.5 角色之间的关系

自己的不同角色可积累本地故事和组合彩蛋，属于角色养成；不同玩家的角色关系映射真实参与的共同事件，属于社交。

本地演出明确标识，不能增加真人关系成果。跨玩家互动由玩家确认或明确预授权，自动台词不能冒充对方本人表达了同意。

## 6. 模块三：社交

### 6.1 关系和空间基础

游戏内稳定账号与好友关系、统一名片、持久家园、开放会客、离线访问、消息中心构成基础。Steam 好友作为后续可接入的关系来源，不作为首轮验证真实多人的唯一依赖。

家园承载长期布置和土地；会客会话承载当下在线成员。关闭会客不删除家园，离线访问权限独立设置。现有常驻公共房间不能自动认定为某玩家的私有家园，需定义归属和迁移。

入口统一：好友、房间成员、邀请卡、植物招募卡均能进入同一玩家名片及获准的家园区域。访问、帮助、赠礼、购买和繁育权限分别判断。

### 6.2 实时互动与异步互动

实时优先复用打招呼、送小心心、请喝茶、一起聊天和合照。发起者选择对象与意图，对方选择回应或使用预授权，双方看到对应动作和共享物件变化。

异步支持礼物、留言、互助记录、繁育申请、任务结果和对成果的欣赏。消息中心区分需要决定的事项、收到的内容和合并动态，普通来访不逐条弹窗。

先使双方真实完成一次来往，再扩展互动花样。任意角色的肢体精确接触不是首轮必要条件，时序、站位、动作意图和共同结果必须清楚。

### 6.3 去朋友家做什么

| 行为 | 来访者价值 | 主人价值 | 经济边界 |
| --- | --- | --- | --- |
| 松土、照料 | 有意义的帮助、小额资源或共同项目进度 | 有上限的生长帮助、来访记忆 | 按账号与植物限定有效次数 |
| 摸花、欣赏 | 发现收藏、轻反馈、观察记录 | 被看见、可回应 | 不无限增加原物售价或稀有基因 |
| 邀请繁育 | 互补性状、子代与谱系 | 子代与新的合作关系 | 双边成本、资格及分配先说明 |
| 买朋友的物品 | 获得想要的收藏或材料 | 出售收益、具体交易记录 | 玩家资产转移与系统售卖分开 |
| 访问特色商店 | 发现不同货源、稀有货品 | 小屋成为值得再来的地方 | 明确个人或共享库存与限购 |
| 参与高价收购 | 按需求交付，获得较高回报 | 形成带着物品来访的理由 | 系统出资属于货币投放，单列预算 |

“高价买东西”保留两种产品用途：玩家愿意高价买朋友的稀有成果；系统高价收购为拜访制造机会。价格由谁设、由谁出钱、库存属于谁，必须在各自入口中清晰表达，不将三者混为一个商店。

首轮商店建议先验证好友家特色系统货架或高价收购中的一个，再接完整玩家交易；玩家买卖仍在总范围内。稀有货架要带来回访理由，同时限制靠好友数量、跨房间刷新和倒卖无限增发价值。

### 6.4 一起挂机：进度成长与关系成长

共同挂机是本轮明确纳入的方向，替代旧公共房间方案“共处不产生额外成长”的产品限制。正式数值尚未启用，不能把目前房间在线时间直接补发为历史关系或经济奖励。

玩家可主动选择一个共同项目，例如一起养一盆花或推进一项会客主题；双方在指定会客空间有效共处时，推进项目并积累这段关系的共处记录。无需持续聊天或反复点击来证明在场。

同时管理三项产出：原有个人挂机积累、共同项目进度、关系成长。三者可以并存，但额外经济收益必须有上限，不能按人数无限乘算或重复叠加多个房间。

断线后保留已获得进度；离线期间是否继续推进项目由项目规则决定，不能计作双方共同在线时间。休眠、挂机异常、账号重复领取和多人加入退出按服务端规则结算。

关系成长可同时来自有效共处、互助、回应和共同完成项目，不要求只靠礼物或刷在线时长。关系里程碑应解锁新的共同表现、纪念或活动选择，不能只增加一条无用途的经验条。

### 6.5 更高级的社交追求

区分三种可见价值：

- 关系成果：双人纪念、共同谱系、关系头像框、合照和互动彩蛋。
- 收藏与投入：稀有植物、主题家具、配饰、出场与迎宾效果。
- 真实受欢迎程度：获得的主动欣赏、回访与邀请，不直接等同于充值。

配饰与头像框可以存在不同获取系列；界面说明来源，付费珍藏与共同成就均有自己的可辨识设计。不是所有高级外观都必须售卖，也不是所有外观都必须免费同速获取。

### 6.6 发现新关系

在小圈子来往成立后扩展植物展示、性状检索、公开繁育招募、开放会客列表和世界聊天。招募承载可查找的合作需求，不能只依赖快速滚动的聊天。

陌生人进入遵守家园开放设置。屏蔽阻止新联系，已开始的共同资产任务仍按原约定独立结算。邀请可以拒绝、撤销或过期，拒绝不公开惩罚关系。

## 7. 模块四：分享裂变

目的：把真实角色魅力、个人成果和共同经历变成接收者能参与的入口，形成分享、到达、体验和留下的完整路径。

| 分享对象 | 展示内容 | 接收者下一步 |
| --- | --- | --- |
| 角色 | 外观、代表动作、人设简介、作者 | 预览并导入，完成直接互动 |
| 特殊植物 | 性状、来源、谱系、真实收获 | 看收藏、了解玩法或发起获准合作 |
| 小屋与配饰 | 布置、穿戴、主题效果 | 参观开放空间、查看获取路径 |
| 共同经历 | 繁育结果、合照、特殊角色互动彩蛋 | 加入双方同意公开的会客或活动 |
| 新用户邀请 | 明确双方奖励、参与步骤 | 创建账号、体验角色、完成一次真人来往 |

邀请奖励按有效新用户体验结算，不只按点击或注册发放。双方得到能帮助一起玩的物品或纪念；奖励总量计入经济账，已存在账号、撤回、异常邀请和重复领取有明确处理。

特殊角色组合可触发彩蛋，优先使用可用动作、物件和时序编排；专用双人素材另行制作。彩蛋不默认消耗付费生成额度。公开分享多人合照或关系信息时，遵守双方的可见性选择。

首轮先提供一种可预览、可到达对应体验的角色或成果分享路径；分享渠道、平台账号和具体奖励参数在增长专项 spec 中确定。

## 8. 模块五：商业化

### 8.1 商业目标与方法

目标是建立多人体验支持的持续收入，并覆盖模型、服务与内容成本。采用商业化 skill 的价值交换、玩家动机分层、数值三线、供需预算、价值感知与增量验证方法。

“多人必需”和本项目对随机机制的重视来自用户的产品决定；课程方法用于推导和验证，不把课程写成“只要多人加抽取就一定赚钱”的依据。

设计顺序：玩家想要什么 → 在哪里看见价值 → 怎样参与并积累 → 哪个差异值得付费 → 购买后怎样使用和展示 → 是否带来持续满意与复购。

### 8.2 身份差异必须有体验承载

| 价值 | 载体候选 | 被看见的场景 | 购买后价值确认 |
| --- | --- | --- | --- |
| 审美与空间风格 | 成套家具、窗景、主题场景 | 来访、会客、分享小屋 | 房间明显改变，可实际布置与使用 |
| 稀缺收藏 | 珍藏家具、角色配饰、主题头像框 | 名片、角色同屏、植物展位 | 形象可辨识、来源清晰、收藏可追踪 |
| 社交表达 | 礼物包装、信纸、合照主题、迎宾效果 | 赠礼、回应、共同记录 | 对方能看到这次选择的表达 |
| 便利与时间 | 研究支持、有限加速、明确用途的资源包 | 玩家已选择的目标页 | 显示减少的等待或补齐的缺口 |
| 创作工具 | 角色或动作生成服务 | UGC 创建流程 | 获得可用资产，费用与生成范围清楚 |

阶层感在本项目中具体表现为收藏、投入与展示效果的差异。普通玩家仍有完整参与合作与表达的能力；高投入玩家的稀有展示有识别度。能否赢得他人回应仍取决于真实来往，不能直接出售虚构人气。

### 8.3 随机机制

将用户提出的随机刺激落实为天气变异、亲本遗传、稀有货架和珍藏抽取四类体验。免费玩法也应有发现和揭晓，付费随机主要承接玩家已经理解的主题与珍藏目标。

每条成长路线要绘制完整获取路径，统计连续随机门槛、平均与最差投入、失败结果用途。避免一个目标同时被低概率天气、低概率变异、低概率遗传、低概率蓝图和失败制作五层阻断。

付费随机要求：逐项概率与实际一致；有明确的目标选择、保底或累积兑换路径；重复结果有用途；断线保留结果与进度；演出可跳过；蓝图与成品明确区分。概率、价格、次数上限与跨池规则须在商品专项设计中计算，不沿用旧稿即上线。

不采用假中奖、假差一点、隐瞒必需制作成本或根据个人付费历史暗改中奖概率。本文的随机商品为不可提现的虚拟内容；首轮不引入付费随机产物自由转售和现金回购。

### 8.4 商品与推出顺序

多人切片阶段就设计可预览、可展示的普通款与珍藏款差异，观察玩家是否理解和想要。真实售卖在支付交付、资产结算、基础体验和商品可用性验证之后启用。

建议先以少量主题成品验证确定购买价值，再引入一个规则完整的珍藏池。家具池、配饰池、月卡和礼包不同时全铺；每个商品只说明主要承接的价值及其触发场景。

角色不以私人记忆或亲近承诺向用户施压消费。关系成果不因付费减少，也不因断签回收。发行地区、渠道及年龄相关商品要求在正式付费上线前单独核验，本文不作法律适用性结论。

### 8.5 收入与利润口径

工具生成收入与游戏内购收入分开记录。商业验证同时看留存、转化、复购、退款、内容消耗和贡献利润。

贡献利润口径：净收入减去模型调用、素材生成、服务分发及其他随用户量变化的成本；研发、美术和运营固定投入另行纳入整体回本模型。不能只以抽取消耗或充值流水宣称产品赚钱。

## 9. 跨模块数值与经济规范

### 9.1 三条线统一

| 线 | 设计对象 | 必须回答 |
| --- | --- | --- |
| 进度线 | 首次体验、章节、每日与共同目标 | 玩家下一步做什么，做完能看到什么？ |
| 成长线 | 物种研究、繁育能力、关系里程碑、收藏与制作解锁 | 新能力带来哪些选择？ |
| 资源线 | 金币、植物、材料、货币、资格、券与有限时间 | 从哪产出、向哪消耗、是否可达且可持续？ |

### 9.2 统一账本范围

基础生产与出售、订单、原有挂机箱子和点数、天气、肥料、繁育、互助、共同挂机、邀请奖励、商店、旅行、家具、抽取及付费资源必须进入同一套产消模型。保留两类货币的设计空间，但名称、兑换与供给不在本稿定价。

资产至少分为基础周转资源、进阶材料、珍藏获取权益和关系成果。每项定义来源、去向、归属、可否赠送或交易、保存周期、上限与迁移方式；没有用途的中间货币不新增。

展示不复制经济资产：照片与谱系卡可保留纪念，但已消耗原物不能再卖一次。交易转移与系统产出分别记账，买家支出不一定是系统回收，必须看卖家是否收到同一货币。

### 9.3 必须重算的场景

- 家具优先、研究优先、配饰优先、社交优先玩家的完整支出选择。
- 无好友、固定搭档、多好友、普通与高投入玩家的产出和目标到达时间。
- 每天不同查看次数、错过天气、长时间离线、持续共同挂机的结果。
- 两人繁育双份子代、天气与肥料叠加、稀有货架倒卖、邀请小号与重复奖励的影响。
- 随机结果分布、保底到达、重复补偿和最差路径，不能只计算平均值。
- 普通与稀有植物的库存、金币净增、材料缺口和内容消耗速度。

旧 v0.1 的 5／15／45 日模型、v0.2 的货币价格和抽取概率、当前花园的变异规则均为不同版本的资料，不能直接相乘或拼接。首轮数值需在模块规则确定后统一配置、模拟和小范围实测。

## 10. 模块六：基础设置与可信运行

### 10.1 Token 统计与成本控制

按直接聊天、自由思考、视觉、记忆整理、手账和其他生成用途记录调用次数、输入输出用量、模型及费用。区分供应商返回用量、供应商账单与本地估算；未知成本不能记为零。

提供每日预算、用途开关、自动调用频率与预算余量。主动聊天和后台自动调用分别设置预算，避免自由模式消耗挤占用户主动互动。生图、视频等非 Token 费用单独展示并归入总成本视图。

控制必须发生在请求前：并发预留预算、限制输出和重试，返回后按实际用量核销；估算或供应商延迟有误差时明确提示。接近上限自动降频，达到自动调用上限后停止新自动请求并保留本地互动；在途请求继续结算，不能宣称零超额风险。

重试、超时和失败调用也计入记录，设置退避和单功能并发上限。更换角色、关闭功能、退出或目标失效时丢弃迟到结果。不得为了产生费用统计再触发额外模型调用。

### 10.2 账号、存档与多人资产

服务端管理真实多人账号、正式资产、随机结果、关系事件、交易与任务结算。客户端负责表达玩家选择与展示确认结果。离线可缓存界面和允许的操作意图，但不能自行签发可交易的稀有物或付费权益。

交易和奖励使用唯一事务标识；邀请、接受、扣费、占用、领取和退款具备可恢复状态。并发出售与繁育要么只有一个成功，要么按明确顺序处理，不出现同一物品两处消耗。

旧本地存档保留可访问的纪念与备份，正式资产迁移单独公布映射方案，不静默清空，也不无条件将可编辑测试资产转成可信稀有资产。

### 10.3 权限、内容与运行体验

好友访问、离线参观、邀请、礼物、公开展示和记忆使用分别可控。具备屏蔽、举报、发布频率限制和通知合并。公开 UGC 需有来源、处理和撤下流程。

后台低占用、休眠恢复、窗口可见性、角色播放、3D 暂停绘制、网络重连和异常恢复属于产品验收项。预算耗尽或网络不可用时，已有角色和本地互动仍能使用，并说明哪些正式多人操作尚未提交。

## 11. 系统分工与事件连接

| 系统 | 管理的对象 | 对其他模块提供什么 |
| --- | --- | --- |
| 角色与素材 | 角色身份、人设、动作、封面、UGC 版本 | 可用动作与展示素材 |
| 陪伴与记忆 | 私人对话、可用事实、互动偏好、调用预算 | 适量回应与可核对的经历表达 |
| 家园与会客 | 布置、土地、访问权限、实时成员 | 持久空间与共同在场 |
| 经济与资产 | 库存、货币、资格、交易、随机结果 | 可信扣发与拥有记录 |
| 任务与关系 | 个人目标、共同任务、有效互动、里程碑 | 下一步行动、成长与纪念 |
| 展示与分享 | 名片、收藏、成果卡、公开范围 | 可见价值与访问入口 |
| 商业与交付 | 商品、订单、权益、退款与成本 | 可理解购买及可靠到账 |

天气、收获、赠礼、帮助、繁育完成、共处结算等先由所属系统确认事件，再触发任务进度、展示与允许写入的记忆。相同事件在不同模块中可以产生不同反馈，但不能重复发放同一份经济奖励。

私人记忆不作为多人资产判定依据；模型不能决定货币扣发、随机结果或玩家是否同意交易。服务器确认失败时显示可恢复状态，不先播放“已送达、已获得”来冒充成功。

## 13. 推进顺序与验收

采用贯穿多个模块的完整体验切片推进，不按六个模块各做一半。下列阶段是依赖顺序，不是已承诺工期。

| 阶段 | 核心交付 | 进入下一阶段的证据 |
| --- | --- | --- |
| A：真实多人体验切片 | 两个真实账号、一个可保存小屋和花园、访问与权限、一次可回应互动、一次异步帮助、一个有限共同挂机项目、一个可见制作目标；同步加入自动调用预算和基础 3D 素材验证 | 两位玩家跨会话完成来往，离线者能接住结果，双方看到一致资产，知道下次为什么再找对方 |
| B：种植合作与收藏追求 | 正式天气变异、双人繁育、谱系、特色商店或高价收购、关系纪念、制作与任务串联 | 合作结果被种下和展示，普通玩家有贡献，稀有资产供给与成长节奏可解释 |
| C：展示、分享与付费验证 | 成套主题、配饰／头像框展示、角色或成果分享、邀请归因、首批明确交付商品、一个完整珍藏池 | 玩家理解价值和获取内容，购买后实际使用展示，分享带来参与，成本与退款可追踪 |
| D：扩大关系和内容 | 公开招募、世界广场、成熟玩家交易、更多共同目标与 3D 场景 | 新关系出现后仍有再次互动，交易和内容产能可持续，经济不依赖持续增发 |

阶段 A 就要展示普通与珍藏内容的体验差异，设计付费价值；不必等大广场和全部内容完成才思考商业化。阶段 C 的真实付费要求先完成对应商品和交付验证，不以阶段名称代替验收。

### 13.1 所有切片共有的验收条件

- 至少以两个独立玩家身份和独立客户端验证，不用本地双角色试演代替真实多人。
- 同时验证在线互动、异步接收、拒绝或撤回、掉线重连、重复请求与旧存档处理。
- 玩家能说明自己的选择、成本、结果，以及结果是否已经完成结算。
- 可用角色、不可用动作、不同尺寸画风和低动态设置均有可接受表现。
- 同一份消耗或奖励不会因重试、切房、重载或改时间重复发生。
- 完成至少一次“目标—行为—反馈—长期结果—再次来往”的完整用户走查。

## 14. 指标与验证方法

产品早期的首要观察是“真实玩家是否围绕具体成果持续来往”。只看房间在线人数、发消息量、点击奖励量不足以判断成立。

| 领域 | 主要观察口径 | 同时检查 |
| --- | --- | --- |
| 多人关系 | 在本期有有效互动的账号对中，下一观察期再次互动的比例；按不同互动类型拆分 | 是否仅为领取奖励，是否总是单边发起 |
| 体验完成 | 从进入目标到完成、使用／展示结果的玩家比例 | 卡在哪一步、是否理解用途、失败恢复 |
| 异步来往 | 收到有效帮助或礼物后查看、回应、回访的比例 | 消息打扰、未读积压、强制回礼感 |
| 繁育 | 邀请理解与接受、完成领取、子代种下及后续分享 | 普通亲本参与、资格枯竭、稀有复制 |
| 共同挂机 | 项目开始、共处贡献、完成与再选项目 | 多账号刷取、单纯空挂、个人玩法被挤出 |
| 陪伴 | 持续启用、主动互动与记忆纠正情况 | 静音／停用、重复气泡、模型费用、卡顿 |
| 分享 | 分享到达、角色导入或入局、有效邀请、后续留存 | 奖励刷取、仅注册不体验、分享隐私 |
| 商业化 | 展示、查看获取路径、购买、使用展示、复购与贡献利润 | 退款、留存、免费玩家参与、内容耗尽 |
| 经济 | 按来源拆分产消比、库存分布、目标到达时间分布 | 通胀、破产、随机最差路径、跨系统套利 |

在测试前固定分母、有效事件、观察窗口和样本分组，并记录配置版本。当前没有可靠基线，本文不虚构转化率、收入或留存阈值。

早期采用小范围真人走查和跨日观察；可做实验时按房间或关系群组分配，避免同一群内奖励和价格相互污染。一次优先改变一个关键变量，区分赠送内容、活动新鲜感和多人机制本身的影响。
