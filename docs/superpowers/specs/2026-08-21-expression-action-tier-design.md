# QBot 表现力动作档（M 档）：动作设计与 Prompt

> 版本：v1.0（2026-08-21）
> 上游文档：`2026-08-21-desktop-behavior-and-rule-engine-design.md`（行为体系）、`prompts.ts`（S 档 6 动作）
> 本 spec 范围：在 S 档 6 个基础动作之上新增一档 12 个表现力动作，含完整 prompt 文案（人形/高保真/抽象三变体）与生成策略。

---

## 0. 前提

S 档 6 动作（`idle` / `drag` / `sleep` / `tea` / `talk_happy` / `talk_annoyed`）解决的是**常驻状态**：站着、被拖、睡着、闲着、说好话、说怪话。它们是「桌宠此刻处于什么状态」。

行为体系 spec 需要的是另一类东西：**一次性表演**。指、扔、捧、背过身、探头、写字——它们不是状态，是**动作节拍**，播完要回到 `idle`。M 档整档都是这一类，播放语义默认 `loops: 1` 后回落，而非 S 档的粘性循环。

---

## 1. 从行为体系倒推

M 档不是「多做点动作更丰富」，每一个都对应行为 spec 里已经写死的需求。没有对应需求的动作一律不进这一档。

| 行为家族 | 缺什么 | 本档补 |
|---|---|---|
| 举证 | 指认屏幕上的东西、郑重出示 | `point` `present` |
| 做戏 | 投掷、探头张望 | `throw` `peek` |
| 留痕 | 写便签 | `write` |
| 沉默 | **整族没有资产**，只能靠不播动画硬撑 | `turn_away` |
| 联机 | 打招呼 | `wave` |
| 元层(agent) | 在旁边看同行干活、损人设的坏笑 | `watch` `smug` |
| 情绪基座 | LLM 的 `mood` 字段目前只能落到 6 个状态动作上 | `surprised` `worried` `cheer` |

其中三个值得单独说：

**`smug`（得意坏笑）是损人设的物理载体。** S 档的 `talk_annoyed` 是「不耐烦地抱怨」，那是被惹烦；损是「我看穿你了」，两者情绪完全不同。所有吐槽、反成就、agent 嘴替评论都要落在这个动作上，没有它整个损人设都演不出来。

**`worried`（担心/欲言又止）是反差机制的物理载体。** 行为 spec §12 的隐性反差——一个损了一个月的桌宠突然正经一次——如果没有一个能表达真诚关心的动作，那一刻只能配 `talk_happy`，反差直接塌掉。

**`turn_away`（背过身）是唯一能把「负成本家族」变成资产的动作。** 沉默类的传播机制是「收回表演」，但完全不动看起来像卡死；背过身 + 偶尔回头瞄一眼再转回去，才是「在闹别扭」而不是「挂了」。

## 2. 技术约束（据现有代码实测确认）

写 prompt 前必须服从的六条，其中三条是这次读代码才确认的：

**循环闭合。** 首帧同时作 `first_frame` + `last_frame`，所以每个动作必须在 5s 内**回到起始姿势**。投掷写成「蓄力 → 甩出 → 收回蓄力姿势」而不是「蓄力 → 甩出」。

**「不位移」= 水平不能跑，垂直很宽容。** `normalizeFilter` 的 `cx` 取全帧 union bbox 的水平中心，角色在画面里横向移动会导致两端偏出画面；而缩放按 `coverage`（平均不透明面积占比）而非 bbox 高度，`footY` 取 union 的最低宽行。结论：**举手、张臂、蹦跳、下蹲都安全**，不会被压小也不会飘。`cheer` 因此可以真跳。

**空手动作 vs 带道具动作，必须提前分好。** 道具画进视频里就被抠像固化了，app 没法换内容。

- 道具进视频：`write` 的笔（笔本身没有内容）
- **手里必须空**：`present`（奖状由 app 合成，同举牌机制）、`throw`（扔的是桌面图标精灵，由 app 生成）
- 空手动作的 prompt 必须**逐项排除**模型爱自作主张塞的东西（球、石头、纸张、卡片），只写「手中空无一物」是拦不住的

**关键帧时刻需要新字段。** `throw` 甩出的那一瞬间、`present` 双手举到位的那一刻，app 要在精确时机生成飞出的图标 / 淡入奖状。建议 `ActionSpec` 增补可选 `cueMs?: number`，由我们出这一档时人工标定（看一遍成片填个数），不做自动检测。没有它这两个动作就只能靠猜时间，会明显不同步。

**朝向统一朝右，左向靠镜像。** S 档的 `talk_*` 已经统一「四分之三侧身朝向画面右侧」（举牌在右侧）。M 档的 `point` `throw` `watch` `peek` 沿用同一朝向，需要朝左时 app 侧 `scaleX(-1)` 即可，**不重复生成一份**，省一半钱。

**`peek` 不能靠「出画遮挡」实现。** 直觉写法是让角色一半被画面边缘挡住，但抠像后角色就真的只剩半个，归一化会把这半个放大到统一尺寸，彻底坏掉。所以 `peek` 必须是**完整角色做出探身张望的姿态**，遮挡由 app 侧 CSS clip 实现。

## 4. Prompt 文案

写法严格沿用 `prompts.ts` 现有措辞习惯：pose 描述首帧静态姿势并逐项排除干扰物，motion 以「角色不位移。」收尾；高保真档只改 motion（去掉耳朵，换头发/衣角），全档禁提尾巴。

### 4.1 point 指认

```
人形 pose：
角色四分之三侧身朝向画面右侧，自己的一只手臂抬起向画面右前方伸直指出，食指明确指
向右前方，另一只手自然下垂，表情认真中带一点得意。角色自身的手和双臂保持自然可见，
手中不持任何物体，画面中不出现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色保持指向画面右前方的姿势，手臂小幅前后点动强调所指方向，头随之朝同方向偏转，
眉毛上扬，耳朵竖起。手臂始终不放下，角色不位移。

高保真 motion：
角色保持指向画面右前方的姿势，手臂小幅前后点动强调所指方向，头随之朝同方向偏转，
眉毛上扬，头发随动作轻轻晃动。手臂始终不放下，角色不位移。

抽象 pose：
角色整体朝画面右侧倾斜前探，姿态像在明确示意右前方。没有其他任何人物或物体。

抽象 motion：
角色朝画面右前方小幅前后点动，像在反复强调那个方向。角色不位移。
```

### 4.2 smug 得意坏笑

```
人形 pose：
角色四分之三侧身朝向画面右侧，微微仰头眯眼坏笑，嘴角单边上扬，一只手抬到胸前手背
轻贴下巴，表情得意。角色自身的手和双臂保持自然可见，手中不持任何物体，画面中不出
现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色眯眼坏笑，肩膀随着无声的窃笑一耸一耸，头微微左右晃动，偶尔挑一下眉，耳朵得意
地抖动。角色不位移。

高保真 motion：
角色眯眼坏笑，肩膀随着无声的窃笑一耸一耸，头微微左右晃动，偶尔挑一下眉，头发随之
轻轻晃动。角色不位移。

抽象 pose：
角色朝向画面右侧，整体微微后仰上扬，姿态透着得意。没有其他任何人物或物体。

抽象 motion：
角色整体一耸一耸地小幅抖动，像在无声地窃笑，偶尔轻轻左右摇晃。角色不位移。
```

### 4.3 cheer 庆祝欢呼

```
人形 pose：
角色正面朝向画面，双臂高高举起向上张开，张嘴大笑，眼睛弯成月牙，表情兴奋雀跃。
角色自身的手和双臂保持自然可见，手中不持任何物体，画面中不出现彩带、不出现礼花、
不出现任何符号或文字，不出现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色举着双臂原地欢呼跳跃，双臂上下挥动，落地后再次跃起，笑容灿烂，耳朵随跳跃上下
弹动。角色始终在原地上下跳动，左右不位移。

高保真 motion：
角色举着双臂原地欢呼跳跃，双臂上下挥动，落地后再次跃起，笑容灿烂，头发随跳跃上下
飞扬。角色始终在原地上下跳动，左右不位移。

抽象 pose：
角色整体向上舒展张开，姿态兴奋雀跃。没有其他任何人物或物体。

抽象 motion：
角色在原地上下弹跳欢呼，每次落下后再次弹起，整体随之舒展收缩。角色始终在原地上下
跳动，左右不位移。
```

> 垂直大幅跳动经确认安全：缩放按 coverage 而非 bbox 高度，基线取 union 最低宽行（落地帧），跳起读作真跳。

### 4.4 turn_away 背过身

```
人形 pose：
角色背对画面站立，只看得到后脑和背影，头微微偏向一侧像在赌气，双臂在身前交叉抱起
（从背后看得到手肘的轮廓）。画面中不出现其他人的手或身体部位，不出现任何额外人物
或物体。

人形 motion：
角色背对画面站着不动，只有肩膀随呼吸轻微起伏，中途头微微转向侧后方瞄一眼又立刻扭
回去，耳朵向后压。角色不位移。

高保真 motion：
角色背对画面站着不动，只有肩膀随呼吸轻微起伏，中途头微微转向侧后方瞄一眼又立刻扭
回去，头发随扭头轻轻甩动。角色不位移。

抽象 pose：
角色整体背朝画面，轮廓偏向一侧，姿态像在赌气。没有其他任何人物或物体。

抽象 motion：
角色背朝画面一动不动，只有整体随呼吸极轻微起伏，中途朝侧后方微微转了一下又立刻转
回去。角色不位移。
```

### 4.5 surprised 惊讶

```
人形 pose：
角色正面朝向画面，身体微微后仰，双眼瞪大，嘴巴张成小圆形，双手抬到胸前手掌张开，
表情吃惊。角色自身的手和双臂保持自然可见，手中不持任何物体，画面中不出现感叹号、
不出现任何符号或文字，不出现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色猛地一惊向后仰，双手抬高，随后眨了眨眼慢慢回到原来的姿势，耳朵先竖直再放松。
角色不位移。

高保真 motion：
角色猛地一惊向后仰，双手抬高，随后眨了眨眼慢慢回到原来的姿势，头发随后仰轻轻扬起
再落下。角色不位移。

抽象 pose：
角色整体向后仰倾，轮廓微微张开，姿态吃惊。没有其他任何人物或物体。

抽象 motion：
角色猛地向后一缩再向外一张，随后缓缓回到原来的姿态。角色不位移。
```

### 4.6 worried 担心

```
人形 pose：
角色四分之三侧身朝向画面右侧，眉毛内侧上抬呈八字形，眼神向下看，嘴唇抿成一条线，
一只手抬到胸前轻轻攥着，表情担心。角色自身的手和双臂保持自然可见，手中不持任何物
体，画面中不出现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色担心地看向画面右下方，轻轻叹了一口气，肩膀随叹息落下又抬起，中途抬眼看一下前
方又低下去，耳朵微微下垂。角色不位移。

高保真 motion：
角色担心地看向画面右下方，轻轻叹了一口气，肩膀随叹息落下又抬起，中途抬眼看一下前
方又低下去，头发垂落轻轻晃动。角色不位移。

抽象 pose：
角色朝向画面右侧，整体微微下沉收拢，姿态显得担心。没有其他任何人物或物体。

抽象 motion：
角色整体缓缓下沉像叹了口气，随后又轻轻抬起，中途朝前方微微探了一下又收回。角色不
位移。
```

### 4.7 present 双手捧举（空手，奖状由 app 合成）

```
人形 pose：
角色正面朝向画面，双手向前平举到胸前，掌心向上并拢摊开，像正在托举展示某样东西，
微微仰头，表情认真而郑重。角色双手掌心之上完全空无一物，画面中不出现纸张、不出现
卡片、不出现托盘、不出现任何物体或文字，不出现其他人的手或身体部位，不出现任何额
外人物或物体。

人形 motion：
角色保持双手向前托举的姿势，手臂随呼吸极轻微起伏，郑重地朝前点了一下头，视线看向
正前方，耳朵竖起。双手始终保持托举姿势不放下，掌心之上始终空无一物，角色不位移。

高保真 motion：
角色保持双手向前托举的姿势，手臂随呼吸极轻微起伏，郑重地朝前点了一下头，视线看向
正前方，头发轻微自然飘动。双手始终保持托举姿势不放下，掌心之上始终空无一物，角色
不位移。

抽象 pose：
角色正面朝向画面，整体前端微微上抬前伸，姿态郑重，像在托举展示什么。角色前方完全
空无一物，画面中不出现任何物体或文字，没有其他任何人物或物体。

抽象 motion：
角色保持前伸上抬的姿态，整体随呼吸极轻微起伏，郑重地朝前点动一下。角色前方始终空
无一物，角色不位移。
```

> `cueMs` 标定：双手到位并稳定的时刻，app 在此淡入奖状。

### 4.8 watch 抱臂围观

```
人形 pose：
角色四分之三侧身站立，头转向画面右侧看着旁边，双臂在胸前交叉抱起，眉毛一高一低，
嘴角平直，表情像在饶有兴致地旁观。角色自身的手和双臂保持自然可见，手中不持任何物
体，画面中不出现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色抱着双臂看向画面右侧，视线缓慢地跟着什么左右移动，中途挑了一下眉，缓慢眨眼，
耳朵朝右侧转动。角色不位移。

高保真 motion：
角色抱着双臂看向画面右侧，视线缓慢地跟着什么左右移动，中途挑了一下眉，缓慢眨眼，
头发轻微自然飘动。角色不位移。

抽象 pose：
角色朝向画面右侧，整体重心微微后靠，姿态像在饶有兴致地旁观。没有其他任何人物或物体。

抽象 motion：
角色朝向画面右侧缓慢地左右转动，像在跟着什么移动的东西看，中途轻轻起伏一下。角色
不位移。
```

### 4.9 throw 投掷（空手，被扔物由 app 生成）

```
人形 pose：
角色四分之三侧身朝向画面右侧，一只手臂高高抬起向后拉到耳侧蓄力，身体微微后仰重心
压在后腿上，表情用力，像正要奋力朝右前方投出什么。角色手中完全空无一物，画面中不
出现球、不出现石头、不出现任何被投掷的物体，不出现其他人的手或身体部位，不出现任
何额外人物或物体。

人形 motion：
角色蓄力后猛地把手臂向画面右前方甩出完成一次投掷，身体随之前倾，随后收回手臂重新
回到向后蓄力的姿势。角色手中始终空无一物，双脚始终停在原地不位移。

高保真 motion：
角色蓄力后猛地把手臂向画面右前方甩出完成一次投掷，身体随之前倾，头发随甩动扬起，
随后收回手臂重新回到向后蓄力的姿势。角色手中始终空无一物，双脚始终停在原地不位移。

抽象 pose：
角色朝向画面右侧，整体向后拉伸蓄力，姿态像正要朝右前方奋力甩出什么。角色周围完全
空无一物，没有其他任何人物或物体。

抽象 motion：
角色向后蓄力后猛地朝画面右前方一甩，整体拉长又弹回，随后重新回到向后蓄力的姿态。
角色停在原地不位移。
```

> `cueMs` 标定：手臂甩到最前的那一帧，app 在此生成飞出的图标精灵。

### 4.10 peek 探头张望

```
人形 pose：
角色侧身朝向画面右侧，重心压低向右前方探出，脖子伸长，一只手虚扶在身前，眼睛睁大
好奇地朝右前方张望，表情小心翼翼。角色完整可见没有被任何东西遮挡，画面中不出现墙、
不出现门、不出现任何遮挡物，不出现其他人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色小心地朝画面右前方探头张望，缓缓探出再缩回一点，如此反复两次，眼睛左右张望，
耳朵警觉地转动。角色双脚停在原地不位移。

高保真 motion：
角色小心地朝画面右前方探头张望，缓缓探出再缩回一点，如此反复两次，眼睛左右张望，
头发随探身轻轻垂落。角色双脚停在原地不位移。

抽象 pose：
角色朝画面右侧压低前探，姿态小心翼翼像在张望。角色完整可见没有被任何东西遮挡，画
面中不出现任何遮挡物，没有其他任何人物或物体。

抽象 motion：
角色朝画面右前方缓缓探出再缩回一点，如此反复两次，像在小心地打探。角色停在原地不
位移。
```

> 遮挡效果由 app 侧 CSS clip 实现，绝不能靠让角色出画（抠像后会只剩半个角色，归一化会把它放大）。

### 4.11 write 写字

```
人形 pose：
角色坐姿低头，一只手握着一支笔按在身前，另一只手扶在旁边，视线专注地落在身前，表
情认真。画面中只有角色和那支笔，没有桌子、没有椅子、没有纸张、没有其他任何人物或
物体。

人形 motion：
角色低头专注地写字，握笔的手小幅左右移动，中途停下来想了一下再继续写，耳朵随之轻
抖。角色不位移。

高保真 motion：
角色低头专注地写字，握笔的手小幅左右移动，中途停下来想了一下再继续写，垂落的头发
轻轻晃动。角色不位移。

抽象 pose：
角色低伏向身前，身前放着一支小笔，姿态专注。画面中只有角色和那支笔，没有桌子、没
有椅子、没有其他任何人物或物体。

抽象 motion：
角色低伏着小幅左右移动，像在专注地涂写，中途停顿一下再继续。角色不位移。
```

### 4.12 wave 挥手

```
人形 pose：
角色正面朝向画面，一只手抬起举到头侧张开手掌像在打招呼，另一只手自然下垂，笑容明
亮，表情友好。角色自身的手和双臂保持自然可见，手中不持任何物体，画面中不出现其他
人的手或身体部位，不出现任何额外人物或物体。

人形 motion：
角色举着手左右挥动打招呼，身体随之轻轻左右摇摆，笑容灿烂，耳朵愉快地抖动。手臂始
终不放下，角色不位移。

高保真 motion：
角色举着手左右挥动打招呼，身体随之轻轻左右摇摆，笑容灿烂，头发随摇摆轻轻晃动。手
臂始终不放下，角色不位移。

抽象 pose：
角色正面朝向画面，整体一侧向上扬起，姿态友好像在打招呼。没有其他任何人物或物体。

抽象 motion：
角色扬起的一侧左右摆动像在挥手，整体随之轻轻左右摇晃。角色不位移。
```

## 5. 抽象档的诚实说明

`point` `throw` `present` `write` 四个本质依赖手部。抽象档只能退化为「整体倾斜前探 / 整体后拉猛甩 / 整体前伸上抬 / 整体低伏涂写」，表现力明显弱于人形档，但**不会凭空长出手臂**（血泪坑 10）。这是有意的取舍：宁可弱，不可长部位。

因此语义匹配（行为体系 spec §6）在抽象角色上要更早退到情绪档兜底——抽象角色的「指」几乎读不出来，不如直接播 `surprised` 或 `smug` 配一句举牌文字。建议匹配器按 `characterForm` 调整这四个动作的匹配分。

## 6. 生成策略与成本

**不进孵化流程。** 每个动作 ≈ 1 次首帧生图 + 1 次视频（视频约 ¥1/条，seedance 轮询最长 15min）。12 个动作串行下来 1~2 小时、¥15~25。孵化现在出 6 个已经要等，再翻三倍会直接劝退。

**三条落地路径，按角色来源分：**

- 官方预置角色：随包出全 12 个，我们自己付钱生成一次，所有用户直接受益
- 用户角色：孵化后在后台**低优先级慢慢补**，或走行为体系 §6 的按需生成闭环——规则命中了但意图词匹配不到时，Studio 提示「你的角色还没有『指认』动作，要生成一个吗」
- 砍半方案：只出前 8 个（`throw` `peek` `write` `wave` 后置），成本降到 ¥10~16

**顺序建议**：`smug` → `point` → `turn_away` → `cheer` 先出。这四个一到位，agent 元层评论 + 沉默类 + done 态立刻就有像样的表演，而这三块恰好是行为体系第 1 档的内容。

## 8. 待定

- `cueMs` 是人工标定还是留空由 app 按比例猜（如 `throw` 取 40%）。倾向人工标定，一次成本极低
- 是否给 M 档也做 GIF（S 档每个动作顺手转了一份 320px GIF 供导出）。12 个动作全转会让角色包体积翻倍，倾向只给会出现在分享图里的几个转
- `write` 的笔是否会因角色画风差异出现违和（写实档握笔可能翻车），需实测一例再决定要不要退化成「空手比划」
