# 方向 C 实机反馈：卡顿、比例和花园加载

用户反馈：突然卡顿，检查是否是本应用内存；花园小面板相对角色过大；独立花园窗口停在“正在打开花园”。沿用已批准的轻量界面方案修复，不新增玩法。

## 观察与修正

- 现场 Windows 总内存约 31.4 GiB，可用约 5.1 GiB。QBot 多进程工作集约 1.8 GiB（含共享页，不能等同独占物理内存），尚无持续增长曲线证明内存泄漏。
- 桌边草地在约 190.5% 缩放的高分屏上持续传输 PNG；旧实现每次绘制都在主进程压缩图片，即使上一帧尚未处理完。改为最多保留一帧待处理原图，确认上一帧后才缩放/压缩，传输宽度上限 1920，刷新上限 12 fps，WebGL 像素比上限 1。保留最终静止帧，避免减少动态效果时漏掉最后更新。原生点击坐标不随传输降采样改变。
- 小面板宽度为角色窗口宽的 1.65 倍，限制在 280–380 DIP，高宽比 1.25。本机约 183 DIP 角色对应 304×380 面板，原先固定 420×560。小屏字号/边距和页签同步适配，移除旧内容区最小高度造成的无效滚动条。
- 空土地使用与背包一致的三列种子格，直接点击播种，不再套用旧的大种子详情卡。紧凑面板不创建额外的果实 3D 画布；空间渲染继续在场景里完成。
- 曾复现数据读取等待超过 7 秒、独立窗口长时间加载，暂停草地后后续读取消耗 0–3 毫秒，原窗口也恢复。不能仅凭这次采样断言全部延迟均由草地引起。首屏读取加 10 秒超时和明确重试入口，避免错误情况下无限等待；不重置存档或回退成假数据。

## 验证

- 类型检查、构建通过；13 项定位/固定窗口/hybrid/帧传输单测通过。
- `scripts/test-direction-c.cjs` 11 类隔离交互通过，新增小尺寸空地、无额外画布/横向溢出、请求挂起后超时与重试恢复。
- `scripts/test-garden-hybrid.cjs` 9 类原生草地回归通过，包括坐标、收获、防重复、模式切换、减少动态效果、关闭与取消启动清理。
- 实机修复后采样：读取 1/2/2 ms，商店打开约 242 ms；角色 183×183，面板 304×380，无横向或无效纵向滚动，紧凑面板 0 个 canvas。
- 实机短时主进程 CPU 约 2.1%（此前约 5%）；进程工作集合计约 1.48 GiB、独占提交合计约 847 MiB。前后窗口数和运行时长不完全一致，属于诊断采样，不是严格性能基准或长期泄漏验收。
- 已正常保存并重启正式客户端。记录与截图在 `output/direction-c-client/performance-check.json`、`live-compact.png`、`live-shop-check.json`；无付费调用、生产种植/收获或真实资产修改。
