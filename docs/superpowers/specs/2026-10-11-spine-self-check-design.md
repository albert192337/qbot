# 新角色生成、自查与有限返工

用户要求：复现佐助右肘向内拐、右腿异常的问题，建立完整自查流程，以明确的 GPT 图像入口创建新角色，记录是否首轮通过。沿用已确认自动校准设计，以下补全验收缺项。

## 成功条件

成功不是“文件可加载”或“178 个动作矩阵有限”。首轮通过须同时具备素材语义、静态关节映射、动态形变、遮挡和视觉复核证据。首轮失败后修好的结果必须标注返工次数，不能称一步到位。没有视觉证据、缺少采样或未知检查均标待复核，不按通过处理。

## 阶段与产物

1. 明确图像入口：会话内置 imagegen、OpenAI 官方 API、第三方兼容 API 分别记账，不互相冒充。文字／视觉审阅模型与图像生成模型分开记录。保留提示词、输入哈希、请求结果、耗时及可取得的 usage；货币账单未知时记 null。
2. 目标图：参考当前骨架同一姿势，视觉隐藏颈部、低薄领边、自然落肩。四肢不预画与骨架相反的弯折；左右使用“角色自身左右＋屏幕左右”双标签。保留身份特征，标注头、下巴、肩、肘、腕、髋、膝、踝。
3. 部件语义：头／躯干／左右完整手臂／左右单腿／五官，检测缺件、粘连、截边、假透明、重复袖子、肤色袖窿、反向鞋尖。关节锚点须在部件范围内且顺序正确。裙摆等无法由六块结构表达的内容不得静默硬塞。
4. 装配：以肩—肘—腕、髋—膝—踝三个锚点建立关节链映射。禁止只独立搬肩头和手腕再插值挤压中段；禁止把上一角色的图集框当成已识别锚点。对完整部件使用分段变换和局部关节混合，袖根搭接与骨骼弯折分开处理。
5. 几何自查：缺失附件、非有限值、权重和、绘制顺序、零长度关节链、关节锚点残差；比较目标关节链与绘制后部件链的有符号弯曲、节段长度比和异常折角。近乎伸直的链不能仅因符号浮动报反向；左右对比先校正透视，不强求像素对称。
6. 动态自查：原模板与新角色同动作同时间；待机、走路、跑步、开心、睡觉、喝茶、抬手，至少八个周期采样；输出整身、头肩、双肘、双膝与部件隔离图。关节方向错误、袖根露缝、肢体被遮掉、鞋子翻转、裙摆穿插分别记录。保留动作名称和采样时间以复现。
7. 视觉复核：审阅目标图、部件和动态联系表，逐项给出通过／失败／不确定，指明角色自身左右、屏幕方向、部位、动作、时间与证据。助手人工看图须标 assistant_review，不冒充独立 API 自动质检。图像生成接口不是视觉 JSON 审阅接口；没有可用审阅 API 时不能宣称后台自动闭环。
8. 有限返工：最多初稿加两次修正。几何偏移重装，方向／缺件／画死的反弯重绘对应部件。每轮保存独立资产、指标和联系表；不改善或出现新硬错误回退，预算耗尽标需人工复核。未经允许不无限调用付费模型。
9. 交付：可播放预览、首轮与最终对比、所有失败项及修正、图片次数／等待时间／实际或未知成本，明确尚未接入的正式创建 UI 和状态映射。

## 必须复现的反例

- 佐助 v5 为用户否定的视觉失败样例，不能作为合格基准。
- 数值全部正常但肘弯方向与指定链相反：必须失败。
- 膝向相反侧折且超过近直容差：必须失败。
- 删掉一侧部件、错误权重和、缺少视觉证据：不得通过。
- 一张静态好看的图不能替代动态检查；8 帧是采样，不代表连续动画所有时刻安全。

## 实施边界

本轮建立本地可重放检查及新角色实验，不部署正式孵化服务。对已存在的脚本补丁不继续宣称为通用校准；新装配器和检查器的自动部分、模型识别部分、人工步骤必须分别披露。本轮在说明默认选择后使用小樱和内置 imagegen 实测；不是独立官方 REST API 调用。实测边界与复跑入口见 `docs/spine-sakura-self-check-trial.md`。
