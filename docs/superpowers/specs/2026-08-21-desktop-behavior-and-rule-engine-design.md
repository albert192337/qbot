# QBot 桌面行为体系：双模式、感知记账、行为脚本与规则引擎

> 版本：v1.0（2026-08-21）
> 上游文档：`DESIGN.md`、`2026-08-16-product-features-and-actions-redesign.md`
> 本 spec 范围：桌宠「自己看、自己想、自己做」的完整体系——感知采集与记账、双大脑（规则/LLM）、受约束行为脚本、语义动作解析、规则引擎、调试面板。不含具体渲染实现细节。

---

## 0. 已确认的决策

| 决策点 | 结论 |
|---|---|
| 模式划分 | 陪伴模式（规则脑，无需 key）/ 自由模式（LLM 脑，用户自带 key）。**两者共用同一执行器与同一行为脚本格式**，不是两套功能，是换个大脑 |
| 模型输出 | 必须是受约束的行为脚本（typed verbs + 白名单参数），不是自由文本。模型只能用**快照里给出的 opaque id** 引用对象 |
| 感知数据分层 | 原始事件流（调试用，**保留 7 天**）/ 账本（桌宠用，长期）/ 行为史（防重复，长期） |
| 账本写入 | **写入时即聚合**，不做事后回扫（原始流 7 天就没了） |
| 行为家族 | 举证 / 做戏 / 留痕 / 沉默 / 联机 / 元层(agent) 六族，共用少数输出通道 |
| 台词三档 | 写死一句 / 台词池随机 / 交给模型（用户定「什么时候」，模型定「说什么」） |
| 规则编辑器 | **仅开发者内部使用**，规则以文件形式随包发布为内置规则包；UGC 与规则包分享后置 |
| 语义动作 | 规则与模型输出**意图词**（吃饭/生气/指），执行器在本地动作库做最近匹配，绝不绑动作 id |
| 调试面板 | 内部工具，先做详细版：四条流 + 回放 + 假快照注入 + 记录钉住 |
| 奖状形态 | 中国小学生奖状风格，模板严肃，模型只填荣誉名与事由；优先级下调至第 3 档 |
| 桌面操作 | **绝不改动真实文件**。「扔图标」扔的是复制品，原图标不动 |
| agent 评论 | 只评论**行为与节奏**（次数/时长/时间点/重复/语气），**永不评论代码内容** |
| 状态机 | 新增 `spont`（自主行为）档，优先级 `drag > agent > meeting > music > visit > spont > auto/idle`，可被瞬间抢占 |

## 1. 目标与不做什么

**目标**：让桌宠产生**未经请求的时刻**。用户输入 prompt 换来的机灵话谁都能复现，没人会分享；传播价值全部来自「我没让它这么干」。

一个片段能传出去要同时满足三条，缺一条就传不动：

1. 一眼看懂，不需要解释设置
2. 只有我这台电脑能产出（具体性 = 不是脚本的证据）
3. 我没让它这么干

由此得出贯穿全 spec 的设计原则：**舞台承担笑点，人设只负责填词**。人设由用户编写，水平参差；如果一个行为的好笑程度等于那行字的好笑程度，长尾用户的桌宠就不好笑。要投资的是结构上就成立的调度，模型只需填「指谁」和「说什么」。

**明确不做**：

- 改动、移动、删除任何真实文件
- 依赖长段落才好笑的行为（长文不流通）
- 需要用户先解释背景才成立的梗
- 让用户觉得被监视而非被陪伴的举证。分界线：**主动开口时只给结论，不报证据链**；用户主动索取时（如成就）才给精确数字

## 2. 四层架构

```
感知通道          →   大脑          →   行为家族      →   可截图产物
──────────────       ─────────         ──────────       ────────────
作息/深夜             规则脑           举证类           举牌一行字
应用台账              (无 key)         做戏类           奖状
桌面项/图标                            留痕类           日记
活动窗口              LLM 脑           沉默类           便签
agent 会话            (自带 key)       联机类           合影
会议/音乐                              元层(agent)      一键存图
交互记录                 ↓
联机邻居           同一份行为脚本 DSL
自身账本           + 主动性预算 + 事件沿触发
```

关键收敛：六个家族不是六套工程，它们共用少数输出通道，**成本几乎全在通道上**。举证类与元层类只需要「举牌 + 奖状」，成本重合；做戏类需要一整套桌面空间演出，单族成本超过前四族之和。这直接决定了 §11 的优先级。

产物层横切所有家族：奖状不是一个家族，是六族共享的输出形态（agent 线可发「本周最佳甲方」，举证可发「原神 87 小时」，联机可发「最佳邻居」）。

## 3. 感知层

### 3.1 通道清单

每个通道独立开关，默认全关（首次引导时逐条征询）。

| 通道 | 内容 | 平台 | 备注 |
|---|---|---|---|
| 作息 | 开机时长、活动时段、最晚活动时刻 | 全 | 由输入事件推导，不记按键内容 |
| 应用台账 | 前台应用名 + 进程身份 + 停留时长 | mac/win | **「玩了 5 小时原神」的真实来源**，与桌面图标无关 |
| 桌面项 | 桌面有哪些文件/应用（名称、图标位图） | 全 | 名称 `ls ~/Desktop`；图标走 `NSWorkspace.iconForFile` / `SHGetFileInfo`，零权限，**不截屏** |
| 桌面坐标 | 图标在桌面上的位置 | win 易 / mac 难 | Windows `LVM_GETITEMPOSITION`；macOS 只能读 `~/Desktop/.DS_Store` 的 `Iloc`，脏且受 Stacks/多显示器影响 |
| 活动窗口 | 前台窗口标题、位置、尺寸、最小化/最大化/全屏状态 | mac/win | 敏感度最高，与应用台账共用独立开关且默认关闭；macOS 详细窗口元数据依赖辅助功能权限，未授权时仍可读应用名；不读窗口正文、不截屏 |
| agent | Claude Code hook 事件 | 全 | 已有，见 `agent-server.ts` |
| 会议/音乐 | 已有 | mac/win | 见 `meeting-monitor.ts` / `music-monitor.ts` |
| 交互 | 被点、被拖、被无视、举牌是否被理 | 全 | |
| 联机 | 周围有哪些桌宠 | 全 | 依赖多人在线 |

### 3.2 三份数据

**原始事件流**（调试用，保留 7 天，本地 append-only，**永不进模型上下文**）
应用切换、窗口标题、图标增删、agent 事件、交互、会议音乐、以及桌宠自己的每次决策快照。

前台记录按语义拆开：真正换应用记 `app_focus`，同一应用内标题/进程元数据变化记 `foreground_change`。后者只用于本地调试记录，不触发 `app_switch` 规则、不增加应用切换计数，也不刷新用户活动/空闲基线。macOS 使用 NSWorkspace + System Events；Windows 使用 User32 + Get-Process。

**账本**（桌宠用，长期保留，体积极小）
应用日累计与连续天数、作息分布滑窗、agent 轮次/报错/打断计数、交互频次、被无视次数、伏笔与兑现记录、已发成就。
**必须在事件写入时同步聚合**——原始流 7 天就没了，当时没统计的东西永久丢失。字段宁可多记。

**行为史**（防重复，长期）
说过什么、发过什么状、哪条规则触发过、用户有没有理。桌宠最快的祛魅方式就是同一句话说两遍。

模型只看账本摘要与行为史，不看原始流。这既是隐私边界也是成本边界。

## 4. 大脑层

### 4.1 双脑同构

规则脑与 LLM 脑输出**同一份行为脚本**。没有 key 的用户拿到的不是残废版，是话少版。

### 4.2 触发时机：事件沿，不是定时器

思考发生在边沿上：切换应用且前一个停留 ≥N 分钟、单应用累计破小时整点、空闲 ≥30 分钟后首次活动、agent `Stop`、会议结束、便签未被理、被连点。边沿合并成一次调用，另加 20~40 分钟的空闲心跳。预估 30~80 次/天。

### 4.3 主动性预算

一个不停说话的桌宠三天就被卸载。硬约束：

- 每小时主动行为上限
- 全屏 / 会中 / agent 干活时硬静音
- 被无视 N 次后自动降频
- 只有确实出现新情况才升频
- **规则不能绕过预算**（否则十条规则把桌宠变成弹窗广告）

## 5. 行为脚本 DSL

```jsonc
{
  "acts": [
    { "t": "play",   "action": "eat", "loops": 2 },          // action 是意图词，见 §6
    { "t": "say",    "text": "…", "ms": 8000 },              // 举牌
    { "t": "moveTo", "target": { "kind": "icon", "id": "i7" } },
    { "t": "point",  "target": { "kind": "window", "id": "w2" } },
    { "t": "toss",   "target": { "kind": "icon", "id": "i7" } },
    { "t": "note",   "title": "…", "body": "…", "sticker": "moon" },
    { "t": "award",  "honor": "屡败屡战奖", "reason": "同一个 bug 连续奋战 6 轮" },
    { "t": "greet",  "peer": "p3" },
    { "t": "photo",  "peer": "p3" },
    { "t": "gift",   "peer": "p3", "item": "lamp_common" },
    { "t": "wait",   "ms": 1200 }
  ],
  "mood": "worried",
  "journal": "主人连续三天两点后还在敲键盘",
  "nextCheckMin": 25
}
```

**执行器是安全层**，三条硬约束：

1. **只能用 id 引用对象**。快照给出 `i7 = 原神`、`w2 = VS Code`，模型不能自己写路径或文件名。执行器校验 id 存在于当前快照，否则整条 act 丢弃。
2. **感知数据是不可信输入**。桌面文件名、窗口标题、联机时别的桌宠名都是他人可控文本，必须放在明确分隔的数据块里，**绝不进指令区**；输出走 schema 校验。
3. **每个 verb 带平台能力位**，执行器按能力表降级，模型不需要知道平台差异。每个 act 有最大时长。

## 6. 语义动作解析

规则与模型输出的是**意图词**（吃饭、生气、指、躲），不是动作 id。执行器在本地动作库做最近匹配。三个理由，一层比一层重要：

1. 每个用户的动作库不同（6 基础 + 各自的自定义动作），绑 id 换个角色就废
2. **我们写的内置规则要发给动作库各异的用户**，只有引用语义才能跨用户成立（将来开放 UGC 时，这也是规则包可分享的唯一前提）
3. 与自定义动作生成形成闭环：匹配不到时 Studio 可提议「你的角色还没有吃饭动作，要生成一个吗」，走现有自定义动作管线。规则需求驱动资产生长

**降级链**：精确名命中 → 在动作名 + `poseDesc` + `motionDesc` 上做语义匹配（有 key 用模型，无 key 用同义词表）→ 退到情绪档兜底（吃饭 → 开心档 → `talk_happy`）→ 提议生成新动作。

匹配结果缓存为「意图词 → 动作 id」绑定，在调试面板中**可见且可人工纠正**（点一次改掉，之后固定）。不要每次都问模型，既贵又不稳。

## 7. 规则引擎

### 7.1 定位

规则提供**必然性**（可靠、可分享、无 key 可用、是共鸣型的梗），LLM 提供**意外性**（不可预测、是惊喜型的）。两条腿都要，不是二选一。

规则编辑器仅供内部使用，规则以文件形式随包发布。**责任因此在我们身上**：规则是产品内容，质量由我们背。

### 7.2 条件面

只开这几类，**多个条件之间只做「与」，不做嵌套**（一旦嵌套，编辑器就变成编程）：

- 时间：星期 / 日期 / 时刻 / 节日
- 桌面：存在某图标、装了某应用
- 使用：某应用今日累计 > N、连续 N 天没开、连续 N 天在开
- agent：某事件、某计数、报错次数
- 会议 / 音乐
- 交互：连点、久未理、久别重逢
- 随机与冷却

### 7.3 效果面

行为脚本 DSL 的子集：说什么 + 意图动作 + 可选的便签 / 奖状 / 指或扔某目标。

### 7.4 台词三档

| 档 | 形式 | 特点 |
|---|---|---|
| 固定 | 写死一句 | 可靠、无 key 可用 |
| 池随机 | 一组台词随机取 | 同一规则不腻 |
| 交给模型 | 只写场景说明 | 每次不同，需 key |

### 7.5 仲裁（必须现在就设计）

写到第十条规则时同一时刻会有三条命中，不定规则就会精神分裂或刷屏：

- 每条规则自带冷却与日上限
- 规则间权重
- 命中多条时只执行一条，其余记入决策日志的「候选未选中」，面板可见
- 全局主动性预算对所有规则硬压制

### 7.6 内置规则包内容取向

出通用向的（深夜、周一、久别重逢、连续加班、agent 嘴硬）。品牌梗与平台梗保鲜期短，硬编码进包里过半年就尴尬，留给后续 UGC。

## 8. 行为家族与产物

按「靠什么传出去」分类，而非按功能：

| 家族 | 机制 | 载体 | 成本 |
|---|---|---|---|
| 举证 | 具体性。选**羞耻或骄傲**两类信号，中性观察没人转 | 截图 | 低 |
| 做戏 | 把用户的东西当道具（指/扔/躲/蹲窗沿） | 视频 | 高 |
| 留痕 | 唯一能在**用户不在场**时工作的一族 | 截图 | 中 |
| 沉默 | 收回默认表演比增加表演更意外 | 截图 | **负** |
| 联机 | 暗示一个世界的存在 | 合影 | 高，依赖在线密度 |
| 元层(agent) | 桌宠自己也是 AI，在看同行干活 | 截图 | **极低，数据已有** |

### 8.1 元层（agent）评论：本产品独有

已拿到的信息：本轮时长、工具调用次数、是否报错、同一件事连续第几轮、提交时刻、仓库名、打断/授权次数、`last_assistant_message` 原文。

四个角度，按有意思程度排：

- **同行视角**（最独特）：「它加班 11 分钟，你在旁边刷手机」「今天第 40 次了，它不累我看着都累」「凌晨两点了，我们 AI 也是要休息的」
- **当用户的嘴替**（潜力最大）：末句是「你说得对」→「它又说你说得对了，今天第 5 次」；「全部测试通过」→「它说全都通过了哦。哦。」踩的是每个 agent 用户的共同经验，只需轻量模式匹配 + 计数
- **举证你在干什么**：「它在跑测试，你在打游戏，合作愉快」「你今天拒绝了它 14 次」
- **功劳归属反转**：「搞定了。它搞定了。你按了个回车」

边界：**永不评论代码内容**。一露怯人设就塌。只评论行为节奏——前者需要真懂，后者只需要会数，而「旁边那个数数的家伙」比「假装懂技术的家伙」可爱得多。

### 8.2 奖状

把举证从「它知道你的事」翻成「它替你认证」，被动的窥视感变成主动的炫耀欲，同一份数据情绪完全反过来，且分享入口天然存在。

```
╔═══════════════════════════════╗
║           奖    状            ║
║                               ║
║   主人 同学：                 ║
║     在 2026 学年第二学期中，   ║
║   于同一个 bug 连续奋战 6 轮， ║
║   表现突出，被评为            ║
║                               ║
║      【 屡 败 屡 战 奖 】      ║
║                               ║
║   特发此状，以资鼓励。         ║
║                        ⊙      ║
║            QBot 桌宠  小绿     ║
║          2026 年 8 月 21 日    ║
╚═══════════════════════════════╝
```

红底金边、齿轮麦穗、烫金字、右下红色篆体圆章、「奖」「状」之间空一格。**模板必须做得完全正经，一点都不能往搞笑偏**——笑点全部来自错位：庄重的国家级模板承载「屡败屡战奖」「今日最废」。模板一旦自己搞笑，错位就没了。

固定不变：「XX 同学」「表现突出，被评为」「特发此状，以资鼓励」。模型只填两处：事由一行 + 荣誉名。用户人设再糟这张纸也不会难看（§1 原则的直接落地）。

**稀缺性三条**（现铸的东西天然不值钱）：

1. **必须会拒发**。什么都发的桌宠发的牌一文不值；会拒绝的评委才有权威
2. 稀有度来自现实难度，不是掉率
3. **反成就传播力大于正成就**。「今日最废」「本周最强嘴硬」用户会主动发，自嘲比自夸安全也更好笑。正向用于炫耀，反向用于传播，反向可能是主力

奖状落地后挂进小房间做**荣誉墙**（复用现有装饰摆放系统），长期积累即可视化，房间截图天然装得进一帧。

### 8.3 分享入口（没有它前面全白做）

用户不会为了截图去开录屏。任何一次自主行为发生后，就地给一键存图/存 GIF，**构图由我们决定**：桌宠 + 牌子 + 相关桌面区域（该模糊的模糊），角标带产品名。行为设计时就要问：这一幕装进一帧是什么样。装不进的要么改调度，要么排后面。

## 9. 调试面板（内部工具，先做详细版）

### 9.1 四条流

1. **我看到了什么**：当前快照全量，含 opaque id 映射
2. **我怎么想的**：命中了哪些条件、候选有哪些、各自打分、为什么选这个
3. **我做了什么**：行为脚本原文 + 每个 act 的执行结果
4. **我为什么没做**：预算耗尽 / 静音窗口 / 冷却中 / 语义动作未匹配 / 被 agent 抢占

第四条是重点。概率系统里「没反应」是最常见状态，面板若不解释沉默，就会一直怀疑是不是坏了。

### 9.2 两个能力（规则功能可用的前提）

**回放**：一条决策记录连同当时快照原地重跑，改台词/改阈值立刻看结果。

**假快照注入**：手动塞入「今天是星期四」「桌面上有原神」「原神今日已 5 小时」并触发一次。没有它，写完星期四的规则要等一周才知道对不对——规则编辑器等于不能用。这同时是我们自己的内容生产线，写梗速度由它决定。

**记录钉住**：防止正在排查的 case 被 7 天清理掉。

内部工具不必设计，直接摊原始 JSON、快照 diff、候选完整打分。将来面向普通用户的「它知道我什么」是**另一个精简只读视图**，两者不合并。

## 10. 隐私边界

- 通道级开关，默认全关，逐条征询
- 前台应用/窗口标题记录由 `foregroundObservationEnabled` 独立控制，默认关闭；关闭后停止采集，既有原始记录仍按 7 天窗口自然清理
- 用户自带 key **不等于**默认可以外发；发给第三方 API 的内容以账本摘要为准，原始流永不出本地
- 键盘监控延续既有边界：只累计次数，哪个键从不离开采集循环
- 联机时明确：别的桌宠不会知道你的应用台账
- 原始流 7 天自动清理，账本可一键清空

## 11. 优先级路线图

排序依据三条：传播力 ÷ 成本；是否为其他部分的地基；**是否需要时间才能生效**（账本类越早埋点越好，否则功能上线当天一片空白）。

**第 0 档 · 地基（桌面上看不出任何变化，但后面每条都压在上面）**
感知采集、账本聚合（写入时）、行为史、决策日志、调试面板四流 + 回放 + 假快照注入、行为脚本 DSL 与执行器、语义动作解析、主动性预算与事件沿调度。

**第 1 档 · 规则与嘴**
规则引擎 + 内部规则编辑器（文件 + 热重载）+ 内置规则包；agent 元层评论上举牌；沉默类。

**第 2 档 · 桌面与身体**
桌面感知（图标清单 → 坐标 → 活动窗口）；指 / 扔（复制品）/ 蹲窗沿；便签条。做戏类整体上移一档，因为规则引擎会自己把这个需求顶上来（写完「星期四 + 原神 → 说话 + 吃饭」，下一条就想写「→ 指着那个图标」）。

**第 3 档 · 账本的出口**
日记、奖状、荣誉墙、两幕伏笔兑现。等账本有货再做，那时几乎是免费的。

**第 4 档 · 社交**
联机打招呼、合影、送礼。做得早只会是空房间。

一句话：先做**嘴和纸**（说什么、记什么账），再做**身体**（在桌面上怎么动），最后做**社交**。嘴和纸天天产出截图，身体产出偶发视频，社交要等人。

## 12. 待定

| 问题 | 现状 |
|---|---|
| 隐性反差维度 | 提议：人设分两层，用户写的显性人格 + 系统保留的隐性维度，在深夜/连续挫败/久别重逢等重锤时刻短暂掉出人设（一周一次量级）。反差是传播力最强的结构，且能救「用户心情差时损人设会伤人」的翻车。**认了的话人设编辑器要按结构化设计，不是以后补。待确认** |
