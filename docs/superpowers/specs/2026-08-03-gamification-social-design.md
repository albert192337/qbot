# QBot 游戏化 + 多人：设计方向（第二版）

## Context

第一版（家具广度 + 奖杯图鉴 + 本地串门）已作废。三条推翻理由：

1. **用户画像不是开发者**，是女大学生 / 白领 → 资源不能来自 Claude Code 时长；CC 只是活动传感器之一（还有 workbuddy 等 agent、网易云音乐）
2. **角色分发靠创意工坊**（规划中，未建）→ 第一版反复纠结的"广度成本"是伪问题；且工坊必然带后端，"第一版不联网"这个约束不成立
3. **调研数据推翻了"奖杯型收集"** → 第一版的核心物料方案（40~60 件家具做广度）方向错误

用户点明的目标：*"要创建玩家想追求、收集的东西，并且创建社交互动的动力——例如去偷花、合作"*，参考 Grow a Garden。

## 调研结论（2026-08-03，来源 Wikipedia；Fandom 全站 402 被拦、WebSearch 该模型不支持）

| | Grow a Garden | Steal a Brainrot | 开心农场 |
|---|---|---|---|
| 上线 | 2025-03-26 | 2025-05-16 | 2008-11 |
| 峰值 | 22.3M CCU | **25.4M CCU**（唯一破 25M 的 Roblox 游戏） | 2300 万 DAU |
| 核心动词 | 种 → 卖 → 解锁稀有 | 偷 → 攒产钱资产 → 防守 | 种 / 交易 / **偷邻居** |
| 人群证据 | "新一代 FarmVille" | 传播素材含大量"丢了资产后哭"（数千万播放） | **约 1500 万城市白领，日均 >5h**；QQ 限每日新增 200 万 |

三条可迁移结论：

**A. 偷 > 单向炫耀。** 后发两个月的偷菜游戏反超了那个破过《堡垒之夜》记录的种菜游戏。第一版的"串门看别人的收集"是单向拉力（看一次就够），偷是双向（我为偷你而回来，你为防我而回来）。

**B. 收集物必须是发动机，不是奖杯。** Grow a Garden 作物**离线也在长**；Brainrot 是 income-generating asset，**被动产钱**。奖杯不产出、不衰变、不需防守 → 既无回访理由也无法被偷（偷奖杯是纯损失，无对冲循环）。花园世界的 262 花同样是奖杯型，靠"团队订单需要它"外挂动力，比"收集物自产出"脆。

**C. 力度按开心农场调，不按 Brainrot 调。** 目标人群历史上正是被偷菜拿下的（1500 万白领），所以"偷"与"合作导向"不矛盾，取决于调参。Brainrot 直接抢存量资产 + Robux 买 traps → 付费军备竞赛，对该人群过火。

## 核心设计

### 1. 在场信号 = 防守机制（QBot 独有）

两个参考游戏的防守都是人工的（Brainrot 按钮护盾 / Grow a Garden 纯计时器）。QBot 已有的活动监测可以直接充当：

- 在岗（有活动信号）→ 桌宠在岗 → 花被守着
- 离开 → 花可被偷

离线增长与离线风险绑在同一个真实信号上。番茄钟"自动开始"（bongo cat 思路）在这个框架里不是独立功能，就是在岗信号本身。**传感器从"给动画换状态"升级为玩法输入** —— 这是 QBot 相对其他桌宠不可复制的部分。

现成实现：`app/src/main/music-monitor.ts`（网易云 SMTC 轮询）+ agent hooks；状态经 `app/src/renderer/pet/state-machine.ts` 驱动动画，牌子由 `refreshSignboard()` 单一来源渲染。新增传感器（workbuddy 等）应复用同一形状。

### 2. 收集物 = 会产出的花

- 花生长（**离线也长**）→ 成熟 → 产花蜜/种子 → 换新品种
- 成熟后有**收取窗口**；窗口内没收 → 可被偷
- 稀有度/变异提供方差（Grow a Garden 的追求引擎：loot box 宠物 + 每周限时 + 稀有黑市）
- 归类分层沿用花园世界第 2 条（分类考核 + 称号），但它是**呈现层**，不是动力来源

### 3. 偷的软调参（四条硬约束）

1. 偷走的是**未收的溢出**，不是存量资产
2. 每日次数上限
3. 留痕迹，被偷方拿到**社交反馈**（"XX 来过，摘了一朵"）而非纯损失
4. 防守免费且可爱（在岗即防守），**不卖道具**

### 4. 角色 = 生产者，不是皮肤

Brainrot 的收集物本身就是会产钱的角色。所以创意工坊的角色应有**产出偏好/特性**，换角色改变玩法 —— 这才让工坊有真实价值。角色本身不可被偷（那是你的桌宠，情绪代价过高），被偷的只有花。

这也解决了第一版"两条轴必须分开"的纠结：角色不再是纯唯一性展示物，它是玩法组件。

### 5. 展示面复用现成资产

等距房间（`app/src/renderer/room/`）已具备：地面/墙面锚定、深度遮挡（`decor.ts` 的 `depthZ`）、家具足迹碰撞（`footprintOf`/`isBlocked`/`truncateAtBlocked`）、角色漫游与拎起（`roam.ts` 的 `step`/`walkTo`）、串门编排、说话（`pet/voice/speak.ts` 的 `Speaker`）、举牌。花园/串门/被偷通知都应挂在这些现成系统上，不新建。

现状缺口：**零积累**。`config.json` 只有设置，全仓库无任何计数器/历史，需要新增 `progress.json`（生长时间戳、库存、称号进度、偷取额度）。

## 明确不做

- 等级 / 战力 / 数值排行榜（违背花园世界第 1 条）
- 抢存量资产、付费攻防道具（Brainrot 的过火部分）
- 偷角色
- 每日任务清单（内容量即成本）
- 把家具做成广度收集轴（奖杯型，见结论 B）

## 未定，需要一起定

1. **方差怎么给才不变成赌博** —— 拿不到 Grow a Garden 的变异概率表与价值倍率（Fandom 被拦），只能调试期实测定。若有其他渠道可补一手数据。
2. **偷的具体数值** —— 开心农场的每日上限/冷却/防守参数同样没拿到。
3. **后端形态** —— 工坊必然需要托管分发；偷花/串门/痕迹可否搭同一套。云自习同意小众，但可先做"朋友活跃时其桌宠出现在你房间"的异步伪同屏，复用现成串门编排，零实时同步。
4. **第一刀切多大** —— 我倾向先只做单机闭环（在岗 → 生长 → 收取 → 换品种），把"偷"留到后端就绪：偷的手感依赖真实好友在线分布，本地假数据调不出来。

## 顺带：已定位未修的 bug

**碰墙不停** —— `DEFAULT_ROOM.floor`（`app/src/renderer/room/rooms/default.ts:115`）可走区域延伸到墙根，而角色高 185px，走到墙边视觉上已穿墙但逻辑上仍在多边形内。修法：`floor` 内侧三边各内收约 45px，一处数据改动，不动逻辑。
