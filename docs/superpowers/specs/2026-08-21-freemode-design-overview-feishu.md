# 桌宠自由模式与桌面行为：设计总览

> 2026-08-21 · 由两篇设计讨论整理：行为体系 + 表现力动作档
> 详细规范见同目录下两篇 spec；本文是给团队快速读的一篇通读版

---

## 一、一句话定位

让桌宠产生**未经请求的时刻**——它自己看、自己想、自己做，行为的结果是能被截图发出去的「我居然没让它这么干」。

一个片段要能传出去，同时满足三条，缺一条就传不动：

1. **一眼看懂**，不需要解释设置
2. **只有我这台电脑能产出**（具体性 = 不是脚本的证据）
3. **我没让它这么干**（用户输入 prompt 换来的机灵话谁都能复现，没人会发）

由此得出全设计最重要的原则：

> **舞台承担笑点，人设只负责填词。**

人设由用户编写，水平参差。如果一个行为的好笑程度等于那行字的好笑程度，大多数用户的桌宠都不好笑。要投资的是**结构上就成立的调度**——同样一句「又是原神啊」，纯文字是一条朋友圈，走过去指着那个图标再抱着头蹲下，就是一条视频。模型只需要填「指谁」和「说什么」。

## 二、模式与整体架构

**陪伴模式（规则脑）**：无需 key，内置规则包，稳定、可靠、可分享。
**自由模式（LLM 脑）**：用户自带 key，模型产出独立行为，不可预测、是惊喜的来源。

两者**共用同一执行器与同一行为脚本格式**——不是两套功能，是换一个大脑。没有 key 的用户拿到的不是残废版，是话少版。

```
感知通道          →   大脑          →   行为家族      →   可截图产物
──────────────       ─────────         ──────────       ────────────
作息/深夜             规则脑           举证类           举牌一行字
应用台账              (无 key)         做戏类           奖状
桌面项/图标                            留痕类           日记
活动窗口              LLM 脑           沉默类           便签
agent 会话            (自带 key)       联机类           合影
会议/音乐                              元层(agent)      一键存图
交互记录                 ↓
联机邻居           同一份行为脚本 DSL
自身账本           + 主动性预算 + 事件沿触发
```

关键收敛：六个行为家族**不是六套工程**，它们共用少数输出通道，成本几乎全在通道上。举证类与元层类只需要「举牌 + 奖状」，成本重合；做戏类需要一整套桌面空间演出，单族成本超过前四族之和——这直接决定了后面的优先级排序。

## 三、感知层：它能看到什么

### 通道清单（每个独立开关，默认全关，逐条征询）

| 通道 | 内容 | 平台 | 备注 |
|---|---|---|---|
| 作息 | 开机时长、活动时段、最晚活动时刻 | 全 | 由输入事件推导，不记按键内容 |
| 应用台账 | 前台应用名 + 停留时长 | 全 | **「玩了 5 小时原神」的真实来源**，与桌面图标无关 |
| 桌面项 | 桌面有哪些文件/应用（名称、图标位图） | 全 | 名称直接列目录；图标走系统 API，零权限，**不截屏** |
| 桌面坐标 | 图标在桌面上的位置 | win 易 / mac 难 | Windows 有公开消息；macOS 只能读 `.DS_Store` 的 `Iloc`，脏且受 Stacks/多显示器影响。第 2 档前做技术验证，不通则 mac 退化为「指活动窗口」 |
| 活动窗口 | 前台窗口标题与边界 | 全 | 敏感度最高，独立开关；mac 取标题需屏幕录制权限，边界与应用名不需要 |
| agent | Claude Code hook 事件 | 全 | 已有现成管线 |
| 会议/音乐 | 已在做 | mac/win | 已有监控器 |
| 交互 | 被点、被拖、被无视、举牌是否被理 | 全 | |
| 联机 | 周围有哪些桌宠 | 全 | 依赖多人在线 |

### 三份数据，三个生命周期

| | 原始事件流 | 账本 | 行为史 |
|---|---|---|---|
| 用途 | 调试排查 | 桌宠的记忆 | 防止重复自己 |
| 保留 | **7 天** | 长期 | 长期 |
| 进模型上下文 | **永不** | 摘要才进 | 摘要才进 |

硬约束：账本必须在事件**写入时同步聚合**——原始流 7 天就没了，当时没统计的东西永久丢失。字段宁可多记。

## 四、大脑层

### 触发：事件沿，不是定时器

切换应用且前一个停留 ≥N 分钟、单应用累计破小时整点、空闲 ≥30 分钟后首次活动、agent Stop、会议结束、便签未被理、被连点……边沿合并成一次调用，另加 20~40 分钟空闲心跳。预估 30~80 次/天。

### 主动性预算（一个不停说话的桌宠三天就被卸载）

- 每小时主动行为上限
- 全屏 / 会中 / agent 干活时硬静音
- 被无视 N 次后自动降频；只有确实出现新情况才升频
- **规则不能绕过预算**（否则十条规则把桌宠变成弹窗广告）

## 五、行为脚本 DSL：模型唯一的输出格式

模型（和规则）输出**受约束的行为脚本**，不是自由文本：

```jsonc
{
  "acts": [
    { "t": "play",   "action": "eat", "loops": 2 },          // action 是意图词，见下一节
    { "t": "say",    "text": "…", "ms": 8000 },              // 举牌
    { "t": "moveTo", "target": { "kind": "icon", "id": "i7" } },
    { "t": "point",  "target": { "kind": "window", "id": "w2" } },
    { "t": "toss",   "target": { "kind": "icon", "id": "i7" } },
    { "t": "note",   "title": "…", "body": "…", "sticker": "moon" },
    { "t": "award",  "honor": "屡败屡战奖", "reason": "同一个 bug 连续奋战 6 轮" },
    { "t": "greet",  "peer": "p3" },
    { "t": "wait",   "ms": 1200 }
  ],
  "mood": "worried",
  "journal": "主人连续三天两点后还在敲键盘",
  "nextCheckMin": 25
}
```

执行器是安全层，三条硬约束：

1. **只能用 id 引用对象**。快照给出 `i7 = 原神`，模型不能自己写路径或文件名；id 不在当前快照里，整条 act 丢弃
2. **感知数据是不可信输入**。桌面文件名、窗口标题、联机时别的桌宠名都是他人可控文本，放在明确分隔的数据块里，绝不进指令区
3. **每个 verb 带平台能力位**，按能力表降级，模型不需要知道平台差异

## 六、语义动作解析：规则与动作之间的桥

规则和模型输出的是**意图词**（吃饭、生气、指、躲），不是动作 id。执行器在本地动作库做最近匹配。三层理由，一层比一层重要：

1. 每个用户的动作库不同（6 个基础 + 各自的自定义动作），绑 id 换个角色就废
2. 内置规则要发给动作库各异的用户，**只有引用语义才能跨用户成立**
3. 与自定义动作生成形成闭环：匹配不到时 Studio 提议「你的角色还没有吃饭动作，要生成一个吗」——规则需求驱动资产生长

降级链：精确名命中 → 动作名 + `poseDesc` + `motionDesc` 语义匹配（有 key 用模型，无 key 用同义词表）→ 情绪档兜底 → 提议生成。匹配结果缓存成「意图词 → 动作 id」绑定，面板可见、**可人工纠正**。

## 七、规则引擎

**定位**：规则提供必然性（可靠、可分享、无 key、是共鸣型的梗），LLM 提供意外性（不可预测、是惊喜型）。两条腿都要。

**条件面**：时间（星期/日期/时刻/节日）、桌面（存在某图标/装了某应用）、使用（今日累计 > N、连续 N 天没开、连续 N 天在开）、agent（事件/计数/报错次数）、会议音乐、交互（连点/久未理/久别重逢）、随机与冷却。多个条件之间**只做「与」，不做嵌套**——嵌套就是编程，普通用户用不了。

**台词三档**：

| 档 | 形式 | 特点 |
|---|---|---|
| 固定 | 写死一句 | 可靠、无 key 可用 |
| 池随机 | 一组台词随机取 | 同一规则不腻 |
| 交给模型 | 只写场景说明 | 每次不同，需 key |

**仲裁**（写第十条规则前必须定）：每条规则自带冷却与日上限、规则间权重、命中多条只执行一条（其余记入「候选未选中」，面板可见）、全局预算对所有规则硬压制。

**规则编辑器仅开发者内部使用**，规则以文件形式随包发布为内置规则包。责任因此在我们身上：规则是产品内容，质量由我们背。UGC 与规则包分享后置，但效果面白名单（只能说话、播动作、指自己桌面上的东西）建议第一天就立住。

## 八、行为家族与产物

按「靠什么传出去」分类，而非按功能：

| 家族 | 机制 | 载体 | 成本 |
|---|---|---|---|
| 举证 | 具体性。选**羞耻或骄傲**两类信号，中性观察没人转 | 截图 | 低 |
| 做戏 | 把用户的东西当道具（指/扔/躲/蹲窗沿） | 视频 | 高 |
| 留痕 | 唯一能在**用户不在场**时工作的一族 | 截图 | 中 |
| 沉默 | 收回默认表演比增加表演更意外 | 截图 | **负** |
| 联机 | 暗示一个世界的存在 | 合影 | 高，依赖在线密度 |
| 元层(agent) | 桌宠自己也是 AI，在看同行干活 | 截图 | **极低，数据已有** |

### 元层：桌宠看 agent 干活（本产品独有）

已拿到的信息：本轮时长、工具调用次数、是否报错、同一件事连续第几轮、提交时刻、仓库名、打断/授权次数、`last_assistant_message` 原文。四个角度：

- **同行视角**（最独特）：「它加班 11 分钟，你在旁边刷手机」「今天第 40 次了，它不累我看着都累」
- **当用户的嘴替**（潜力最大）：末句是「你说得对」→「它又说你说得对了，今天第 5 次」——踩的是每个 agent 用户的共同经验，只需轻量模式匹配 + 计数
- **举证你在干什么**：「它在跑测试，你在打游戏，合作愉快」「你今天拒绝了它 14 次」
- **功劳归属反转**：「搞定了。它搞定了。你按了个回车」

边界：**永不评论代码内容**——一露怯人设就塌，只评论行为节奏（次数/时长/时间点/重复/语气）。「旁边那个数数的家伙」比「假装懂技术的家伙」可爱得多。

### 奖状：把「被监视」翻成「被认证」

同一个数据、同一次曝光，把「它知道你的隐私」翻成「它替你发牌子」，情绪完全反过来，分享入口天然存在。

```
╔═══════════════════════════════╗
║           奖    状            ║
║                               ║
║   主人 同学：                 ║
║     在 2026 学年第二学期中，   ║
║   于同一个 bug 连续奋战 6 轮， ║
║   表现突出，被评为            ║
║                               ║
║      【 屡 败 屡 战 奖 】      ║
║                               ║
║   特发此状，以资鼓励。         ║
║                        ⊙      ║
║            QBot 桌宠  小绿     ║
║          2026 年 8 月 21 日    ║
╚═══════════════════════════════╝
```

- 红底金边、齿轮麦穗、烫金字、右下红色篆体圆章——**模板必须做得完全正经**。笑点全部来自错位：庄重的国家级模板承载「屡败屡战奖」「今日最废」；模板一旦自己搞笑，错位就没了
- 固定文字「XX 同学 / 表现突出，被评为 / 特发此状，以资鼓励」，模型只填**事由一行 + 荣誉名**
- 稀缺性三条：**必须会拒发**（什么都发的评委没有权威）；稀有度来自现实难度不是掉率；**反成就传播力大于正成就**（「本周最强嘴硬」用户会主动发，自嘲比自夸安全也好笑）
- 落地后挂进小房间做**荣誉墙**，复用现有装饰摆放系统

### 桌宠日记 + 便签 + 一键存图

- 日记：零新增动画、模型最擅长、天然可截图，且是「举证 + 留痕 + 伏笔兑现」三者的容器
- 便签：唯一在**用户不在场**时工作的行为；「回来才发现」的时间差是情绪价值核心
- 一键存图：用户不会为了截图去开录屏，素材必须由我们**主动递到手里**。构图由我们决定（桌宠 + 牌子 + 相关桌面区域，该模糊的模糊，角标带产品名），行为设计时就要问：这一幕装进一帧是什么样

## 九、表现力动作档（M 档 12 个）

S 档 6 个解决「桌宠此刻处于什么状态」（站着/被拖/睡着/闲着/好话/怪话）；M 档解决**一次性表演**——指、扔、捧、背过身、探头、写字，播完回落 `idle`。整档由行为体系倒推，**每一个都对应已写死的需求，没有对应需求的不进档**。

### 承重设计（先看这三个）

- **`smug` 得意坏笑**：损人设的物理载体。`talk_annoyed` 是「被惹烦」，损是「我看穿你了」，两种情绪。所有吐槽、反成就、agent 嘴替都落在这，没有它损人设演不出来
- **`worried` 担心**：反差机制的载体。「损了一个月突然正经一次」的瞬间如果只能配 `talk_happy`，反差直接塌
- **`turn_away` 背过身**：沉默类唯一的资产，且必须带「偶尔回头瞄一眼再扭回去」——完全不动看着像卡死而不是闹别扭

### 清单与优先级

| # | 动作 | 解锁 | 意图词 |
|---|---|---|---|
| 1 | point 指认 | 举证/做戏/元层 | 指、指着、指出、就是它 |
| 2 | smug 得意坏笑 | 元层/吐槽/反成就 | 坏笑、得意、嘲讽、看穿 |
| 3 | cheer 庆祝欢呼 | done 态/正向成就/伏笔兑现 | 庆祝、欢呼、太棒了、鼓掌 |
| 4 | turn_away 背过身 | 沉默类整族 | 生气、不理、闹别扭、哼 |
| 5 | surprised 惊讶 | 通用高频 | 惊讶、吓一跳、诶、发现 |
| 6 | worried 担心 | 反差时刻/深夜关心 | 担心、心疼、欲言又止、叹气 |
| 7 | present 双手捧举 | 奖状/便签/出示证据 | 出示、颁发、举起、请看 |
| 8 | watch 抱臂围观 | agent 元层专用 | 围观、吃瓜、看着、审视 |
| — | 砍线 | | |
| 9 | throw 投掷 | 做戏类核心 | 扔、丢、投、甩出去 |
| 10 | peek 探头张望 | 做戏/串门 | 探头、偷看、张望、冒出来 |
| 11 | write 写字 | 留痕类 | 写、记、留言、做笔记 |
| 12 | wave 挥手 | 联机/久别重逢 | 打招呼、挥手、你好 |

### 关键 prompt 思路（全文案见 spec）

- **point**：四分之三侧身朝右，手臂伸直指出，motion 保持手指小幅点动强调、手臂不放下
- **smug**：微微仰头眯眼坏笑，手背轻贴下巴，motion 是肩膀一耸一耸的无声窃笑
- **cheer**：双臂高举张手、咧嘴笑、眼弯月牙。**可以真跳**（见下方技术约束）
- **turn_away**：背对画面抱臂赌气，头中途转向侧后方瞄一眼再扭回去
- **surprised**：正面后仰、瞪眼、嘴张小圆，手抬到胸前张掌。**必须显式排除感叹号**（模型爱乱加符号）
- **worried**：八字眉、向下看、嘴抿成线，一手攥着抬到胸前；motion「抬眼看一下又低下去」是欲言又止的关键
- **present**：双手前平举、掌心向上摊开，**掌心之上完全空无一物**——奖状由 app 合成（同举牌机制），prompt 逐项排除纸张/卡片/托盘/文字
- **watch**：抱臂、头转向右侧、眉毛一高一低，视线缓慢跟着什么移动——专为看 agent 干活设计
- **throw**：手臂拉到耳侧蓄力 → 甩出 → **收回蓄力姿势**（循环闭合）；手中空无一物，逐项排除球/石头
- **peek**：完整角色做探身张望姿态——**不能靠出画遮挡**（抠像后只剩半个角色，归一化会把它放大），遮挡由 app 侧 CSS clip 实现
- **write**：坐姿低头握笔写字，画面中只有角色和笔，无桌无纸
- **wave**：正面举手过头左右挥动，身体轻轻摇摆

### 动作设计的技术约束（读代码实测确认）

1. **循环闭合**：首帧 = 末帧，每个动作 5 秒内回到起始姿势（投掷写成「蓄力→甩出→收回蓄力」）
2. **「不位移」= 水平不能跑，垂直很宽容**：归一化按 alpha 覆盖率而非 bbox 高度缩放，基线取全帧最低宽行——举手、张臂、蹦跳都安全，`cheer` 因此敢真跳
3. **空手 vs 带道具必须提前分好**：道具进视频就被抠像固化了。`write` 的笔进视频；`present`、`throw` 手里必须空（奖状/图标由 app 生成），空手 prompt 必须**逐项点名排除**模型爱塞的东西
4. **新增 `cueMs` 字段**：`throw` 甩到最前帧、`present` 双手到位时刻，app 要在精确时机生成飞出图标/淡入奖状，人工看一遍成片标个数，不做自动检测
5. **朝向统一朝右，左向镜像**：`point` `throw` `watch` `peek` renderer 侧 `scaleX(-1)` 即可，省一半生成钱
6. **抽象档诚实说明**：`point` `throw` `present` `write` 依赖手部，抽象角色只能退化为「整体前探/后拉」，表现力弱但**不会凭空长出手臂**（已有血泪教训）；语义匹配在抽象角色上要更早退到情绪档兜底

## 十、调试面板（内部工具，先做详细版）

**四条流**：
1. 我看到了什么（当前快照全量，含 id 映射）
2. 我怎么想的（命中条件、候选打分、为什么选它）
3. 我做了什么（脚本原文 + 每个 act 执行结果）
4. **我为什么没做**（预算耗尽/静音/冷却/未匹配/被抢占）——概率系统里「没反应」是最常见状态，不解释沉默就会一直怀疑是不是坏了

**两个能力（规则功能可用的前提）**：
- **回放**：一条决策连同当时快照原地重跑，改台词改阈值立刻看结果
- **假快照注入**：手动塞「今天是星期四」「桌面上有原神」并触发一次——否则写完星期四的规则要等一周才知道对不对

面向普通用户的「它知道我什么」是另一个精简只读视图，两者不合并。它同时解决信任与炫耀：用户看见账本页的第一反应可能就是截图。

## 十一、路线图

排序依据三条：传播力 ÷ 成本；是否为其他部分的地基；**是否需要时间才能生效**（账本类越早埋点越好，否则功能上线当天一片空白）。

**第 0 档 · 地基**（桌面上看不出变化，但每条都压在上面）
感知采集、账本聚合（写入时）、行为史、决策日志、调试面板四流 + 回放 + 假快照注入、行为脚本 DSL 与执行器、语义动作解析、主动性预算与事件沿调度

**第 1 档 · 规则与嘴**
规则引擎 + 内部规则编辑器（文件 + 热重载）+ 内置规则包；agent 元层评论上举牌；沉默类

**第 2 档 · 桌面与身体**
桌面感知（图标清单 → 坐标 → 活动窗口）；指 / 扔（复制品）/ 蹲窗沿；便签条。做戏类上移一档，因为规则引擎会自己把这个需求顶上来

**第 3 档 · 账本的出口**
日记、奖状、荣誉墙、两幕伏笔兑现（等账本有货再做，那时几乎是免费的）

**第 4 档 · 社交**
联机打招呼、合影、送礼（做得早只会是空房间）

> 一句话：先做**嘴和纸**（说什么、记什么账），再做**身体**（在桌面上怎么动），最后做**社交**。嘴和纸天天产出截图，身体产出偶发视频，社交要等人。

**动作档首轮出 4 个**：`smug` → `point` → `turn_away` → `cheer`——到位后 agent 元层评论、沉默类、done 态立刻有像样的表演，正好覆盖第 1 档内容。官方预置角色随包出全 12 个；用户角色走按需生成（规则命中但意图词匹配不到时 Studio 提示生成）；预算紧张砍到前 8 个。

## 十二、已确认决策汇总

- 双模式同构：规则脑与 LLM 脑输出同一份行为脚本 DSL
- 模型输出受约束脚本，只用 id 引用对象；感知数据是不可信输入，绝不进指令区
- 感知三份数据：原始流 7 天（调试用，永不进模型上下文）/ 账本长期（写入时聚合）/ 行为史长期
- 台词三档：写死 / 池随机 / 交给模型，用户定「什么时候」、模型定「说什么」
- 规则编辑器仅内部使用，规则文件随包发布为内置规则包；效果面白名单第一天立住
- 语义动作解析：意图词匹配 + 降级链 + 可人工纠正的缓存
- 奖状模板严肃、只填事由与荣誉名；判定权倾向「规则定够格、模型填名目」
- 桌面操作绝不碰真实文件；「扔图标」扔的是复制品
- agent 评论只评行为节奏，永不评论代码内容
- 状态机新增 `spont` 档：`drag > agent > meeting > music > visit > spont > auto/idle`，可被瞬间抢占
- M 档动作一次性播放语义（loops: 1 回落 idle），区别于 S 档粘性循环
- 真实验证要先花钱烟测，先挑 `smug` `throw` 各一条（验表情细节 + 验空手拦不拦得住模型）
