# 聊天“指令”入口

按用户给定交互实现：输入“指令双人打闹”，显示“我可以和XX一起打闹吗？”，本次同意后执行。复用现有授权窗和执行器，不新增聊天模型调用；用户输入的明确动作不交给自主模型决定是否忽略。

只有去除首尾空格后以“指令”开头才触发；可加冒号，支持双人行为、带名字的对象、邀请来玩、收菜、游戏内朋友圈和已拥有的单人动作。未知行为、同名歧义、未知对象、不可用素材与忙碌场景明确返回错误，不伪称成功。多个要求不会被拆成未经逐项授权的执行序列。

双人行为未指定目标时优先真实同场可见角色，其次本地角色库；指定名字时不替换为其他角色。弹窗标出目标及本地邀请/联机对方仍需接受的区别。手动指令用 user 来源，不受自主打扰次数和聊天静默期限制，不要求开启LLM脑；朋友圈仍遵循既有模型设置和生成预算。

采用独立规则解析器加现有授权器。纯模型解析可能继续返回“不行动”；新增另一套弹窗会复制授权逻辑，因此均不采用。人工指令替换仍待答复的旧申请，但不会自动批准；换角、隐藏、离房、资料变化和90秒超时校验保留。正在播放时返回等待提示，不堆积行为队列。

验证覆盖真实聊天入口、不调用模型、目标选择、无Key/关闭自由模式、人工与自主限额隔离、同意/拒绝/重复点击、旧申请替换、场景失效、未知及否定语句。隔离Electron使用正式聊天窗口、正式聊天处理器和授权器，接受后验证双人播放自然结束。不向真人发送测试邀请，不调用付费模型。

验收：类型检查、App构建通过；`pet-command-rules`、`pet-chat`、`autonomy-runtime`、`autonomy-day` 四个文件26项通过。`scripts/test-chat-command-ui.cjs` 使用隔离角色/机会数据、正式聊天表单和处理器、正式授权器及双人播放器，已验证指定对象弹窗、拒绝不执行、立即再次申请、重复同意只发送一次、自然结束及场景失效取消。模型调用0次；截图和结果在 `output/chat-command/`，不是公网真人互动验收。
