# 角色生成、表情包导入与动作管理

状态：2026-09-19 用户确认实施。本文取代故事小屋作为角色管理入口的设计；不改变桌宠、花园和联机房间本身。

## 目标与信息架构

使用普通可缩放管理窗口。左侧直接提供角色库、创建角色、导入表情包、生成任务、连接、市场、设置。选中角色后提供角色资料、动作库、动作配置、高级生成。移除故事小屋场景、房间切换、手册和练习册比喻。编辑对象与桌面角色独立，点击“放到桌面”才激活。

### 2026-09-20 界面修订

用户追加提供 `guokaigdg/animal-island-ui` 截图作为明确参考，视觉依据为该项目的[设计定义](https://github.com/guokaigdg/animal-island-ui/tree/main/docs/design-system)。QBot 继续使用现有 DOM 页面，独立实现样式，不引入 React 组件库或其插画资产。

- 配色：奶油背景 `#f8f8f0`、暖棕正文、青绿主操作、淡黄色当前导航。卡片约 24px 圆角，按钮与单行输入为胶囊形；仅主操作有轻微下压反馈。
- 字体：随安装包提供 Nunito 可变字体用于拉丁字母和数字，中文使用本机雅黑/苹方；运行时不请求在线字体。
- 功能文字直接表意，不恢复故事、练习册、房间切换等导航包装。
- 导入流程只有“选择素材 → 配置动作 → 完成”步骤导航，不叠加角色资料/动作库标签栏。第二步先展示场景配置，再展示资源列表及标注。选动作仍进入带预览的二级多选页。
- 创建角色页在宽度不超过 900px 时使用单列；800×600 窗口中多选确认按钮保持可见，取帧弹窗缩短预览并保留确认区。
- 页面可见性由路由统一管理：离开的页面设置 `hidden` 与 `inert`，保留草稿但不可见、不可点击或键盘聚焦。延迟载入的联机/创建样式只作用于 `.pane[data-pane]`，不得命中侧栏按钮。
- 修改颜色、圆角与字体入口：`app/src/renderer/console/theme.css`；导入与动作选择的专属布局分别位于 `panes/sticker-create.css`、`panes/action-picker.css`。

## 两种创建方式

### 从图片生成

1. 选择参考图片，填写角色名称，选择云端或本地生成；高级选项保留形态、风格和生图服务。
2. 提交后立即进入任务详情。展示形象生成、等待确认、动作生成、完成或失败的真实状态。
3. 形象方案必须由用户确认；换方案属于显式生成操作。关闭窗口、读任务状态、切换页面不提交模型请求。
4. 已确认形象后生成该任务记录的基础动作集合，不能因软件升级自动追加付费动作。
5. 每个动作独立显示状态和错误；成功素材保留，失败项支持恢复。记录已付费视频任务 ID，重启恢复先查询，不重复提交。
6. 完成后可编辑名称、人设和封面，预览动作，显式放到桌面。封面独立于生成参考图。

### 从表情包创建

1. 选择单个角色的 GIF 文件夹。只扫描直接包含的 GIF，不递归读取其他角色。文件名提供初始名称和语义标签。
2. 收集页逐项预览、编辑名称/含义/标签、选择主形象；搜索支持这些文字。资源 ID 和实际文件名保持不变。
3. 配置页为待机、拖拽、睡觉、放松、开心、不高兴、问候、花园及窗沿等场景选一个或多个素材。按名称和标注推荐并预选，低把握场景保持空白。已有配置不自动覆盖。
4. 本地转码无需模型 Key，不上传原件；保留透明通道和原始 GIF，单项失败不丢弃其他素材。主形象必须可取帧，待机必须有可播放素材。
5. 创建后可继续编辑含义和场景，追加生成新动作。语义分析是显式选项，其建议不覆盖人工标注。

## 动作资源与标注

资源由稳定 ID 标识。用户名称（最多 80 字）、含义说明（最多 500 字）、标签（最多 20 个，每个 40 字）是独立元数据，不改变路径、生成提示词或动作绑定。空名称回退已有名称或资源 ID；表情包保留最近保存的名称，不提供历史名称撤销。展示、搜索、推荐和 AI 动作描述使用人工标注优先的统一读取函数。原素材、生成变体和默认动作均可编辑标注。

## 多动作选择

点击场景的“选择动作”打开覆盖当前内容区域的二级选择页。顶部有返回、搜索、推荐/全部/已选，主体使用可预览卡片与复选框，底部固定显示数量、取消和确认。选择先进入局部草稿，取消不改配置，确认回到配置页，最终保存才写入角色。

默认动作保留一个兼容引用，同时新增场景候选列表。旧单选配置迁移成单元素列表；旧待机候选完整保留。第一项为默认项，可调整。待机候选在动作库有明确标记。

运行时只选择存在且可播放的候选。待机规则模式每 3～7 分钟轮换，开启 AI 时在用户选定集合内依据文字语义和情境选择并保持稳定。其他场景在进入时选择一个，持续循环或重复播放期间不跳换。候选失效时回退默认可用动作。推荐依据名称、含义与标签，不声称检测了实际运动幅度或循环平滑度。

待机不可保存为空；其他场景为空时沿用原有默认播放/缺失回退行为，不表示禁用该状态。更改候选不会替换标准资源本身。表情包新导入仅为有明确名称匹配的场景预选，主形象单独选择；推荐页不会自动发起视觉分析。

## 参考帧

从原图、已选形象或已有动作选参考。动作使用与真实时长一致的时间轴，支持拖动预览和秒数精调；最后位置限制到有效帧，切素材重置时间。连续拖动合并请求，过期响应不覆盖新预览，预览未完成不可确认。静态图不显示时间轴。选帧不收费。

## 动作并发生成

不同动作允许同时生成。相同角色共用一个内存任务和串行状态保存，动作级占用防止重复提交同一动作。网络生成不占用角色级写锁；结果按动作合并到最新 manifest，不能覆盖其他任务或用户编辑。

原样角色重新生成流程：选参考帧 → 确认生图 → 生成首帧 → 对照确认 → 生成视频 → 合并成功素材。取消保留待确认首帧和原动作。一个动作等待确认不阻塞其他动作。整角色重建与局部生成互斥。任务进度按动作报告，只有所有进行中的动作完成才报告整体终态。

## 数据与兼容

- `manifest.resourceAnnotations[id]`：人工名称、含义、标签。
- `manifest.scenePools[scene]`：有序资源 ID 列表，兼容原默认动作与 `stickerLibrary.scenes`。
- 表情包 `sceneCandidates` 作为创建/编辑请求候选；旧 `idleCandidates` 同步到统一待机集合。
- `.job/state.json`：参考来源、首帧审核、任务状态、付费视频 ID；只由共享任务实例写入。
- 名称与含义属于可分享资源说明，随角色包保存；人设、密钥、任务记录、生成 prompt 与本地路径继续剥离。

## 失败与交互边界

保存失败保留输入并显示可理解错误。切页面保留草稿，切角色检查未保存修改。后台进度不得重绘并清空编辑内容。生成中的按钮只锁对应动作。离开选择页清理视频、计时器和键盘监听；小窗口内部滚动，确认按钮可达。

表情包资源生成方式、取帧秒数与动作描述作为页面内草稿按角色/源资源保存；取消或提交失败不清空。按钮旁显示校验与生成反馈，成功提交后可直接查看任务或新版本。后台事件刷新新版本区，不重置其他编辑；成功完成的动作从待处理任务列表移出，持续保留在角色的新版本列表中。

## 验收

1. 同角色 A/B 动作并行生成且相互不覆盖；重复 A 被拒绝；一个失败不阻塞另一个。
2. 待确认首帧重启可恢复，未经确认不提交视频；已有付费任务恢复不重复提交。
3. 新导入预选有依据，已有角色不被重配；多选保存重启后保留，桌面使用所选候选。
4. 所有动作可改名和含义，ID/文件路径/绑定不变，搜索和 AI 描述同步。
5. 时间轴拖动、快速切素材、尾帧与取消不会显示过期结果。
6. 默认入口为普通管理窗口，创建与导入不再跳故事小屋；原有连接、奖励和布置入口仍可达。
7. 管线与 App 单测、类型检查、构建，以及隔离数据的 Electron 界面验证。模型请求使用模拟，不以此宣称真实生成效果已验收。

## 页面与保存规则明细

| 页面 | 用户输入/操作 | 保存时点 | 返回与失败行为 |
| --- | --- | --- | --- |
| 创建角色 | 图片、名称、模型与风格 | 点击开始、完成费用确认 | 未提交前保留草稿；失败显示原因 |
| 生成任务 | 查看、确认形象、继续、移除记录 | 显式操作 | 移除记录不删除资产、不停止正在运行的任务 |
| 导入表情包 | 文件夹、主形象、逐项名称/含义/标签 | 点击导入并创建 | 转码失败项单独列出，成功项保留 |
| 动作库 | 视频预览、标注、重新生成 | 每资源“保存标注” | 不改变稳定 ID，不因后台完成丢输入 |
| 动作配置 | 每个基础场景的候选集合 | “保存基础场景” | 选择器确认先改页面草稿；取消保持原选择 |
| 表情包配置 | 自由表达启用、候选、标注 | “保存表达与场景” | AI 建议须手动采用；刷新仅合并生成变体 |
| 角色资料 | 名称、人设、封面 | 各自保存 | 封面不改变原图或生成参考 |

二级选择页最多一页显示 18 项，分页与筛选不丢已选集合；“设为默认”把该资源移到已选集合第一项。视频按需播放，切页暂停。键盘 Tab 在选择页循环，Escape 与取消一致。资源 ID 与文件路径不作为主要界面文案。

## 状态与接口

基础动作阶段：`pending → generating_frame → frame_qc → generating_video → keying → done`，任一步错误进入 `failed`。`needsFrameApproval` 与首帧质检通过同时成立表示“首帧待确认”，不能解释成仍在生成视频。等待确认不占用动作生成操作；再次确认时比较所见首帧与当前保存首帧，拒绝确认过期画面。

| 接口 | 作用 | 是否可能调用收费服务 |
| --- | --- | --- |
| `hatch.start` | 新建角色任务，按云端/本地配置路由 | 是 |
| `hatch.getStatus` | 读取运行或落盘快照 | 否，不续跑 |
| `hatch.resume` | 显式恢复保存的任务 | 是，优先复用已有付费任务 |
| `stickerLibrary.scan/preview/create` | 本地扫描、预览、转码与创建 | 否 |
| `stickerLibrary.analyze` | 抽帧语义建议 | 是，手动选择 |
| `studio.imageChoices/previewImage` | 枚举素材、本地取帧 | 否 |
| `studio.prepareActionFrame` | 保存参考并生成待确认首帧 | 是，仅生图阶段 |
| `studio.approveActionFrame` | 校验首帧并推进视频 | 是 |
| `studio.saveResourceAnnotation` | 保存资源名称、含义、标签 | 否 |
| `studio.saveScenePools` | 校验可播资源并保存场景集合 | 否 |

`manifest-store.editManifest` 串行化读取、修改与原子写入；外部网络调用不放进保存队列。`ActionSessions` 为同角色复用一个 Job，不同动作并行推进，相同动作重复请求报可理解错误。任务列表对补生成使用所选动作的进度，不把原始全套动作中的未选项算作等待生成。等待审核从“管理动作 → 继续确认首帧”进入。

## 当前边界与后续扩展

- 本次并发和逐动作首帧确认针对本地基础动作重新生成。云端角色继续使用既有托管任务协议，本次没有部署服务器。
- 新增预设和自定义动作保留原有后台生成链路；本次为其 manifest 写入增加并发合并保护。它们尚未统一到基础动作的首帧人工确认和持久化视频恢复流程，不能把基础动作的恢复保证推广到这些入口。
- 新角色整包生成仍按原有形象确认流程。表情包创建不生成三视图；基础动作补生成保留原样提示约束。
- 本次推荐为文字规则，不增加自动运动幅度评分、循环平滑度评分或额外付费视觉调用。
- 故事小屋不再是运行入口；旧源码与历史验收脚本保留，物品、布置等独立功能复用其控制器。桌面房间与联机空间是独立功能，并未移除。
- 当前基础场景支持多选；Claude Code、音乐、会议的专门联动配置仍保留既有单动作选项。
- 标注会随角色素材包共享；不要把角色人设或用户私密记忆混入资源说明。
