# 朋友与最近见过

入口：右键桌宠 → 一起玩 → 朋友。首页「打开朋友列表」也可进入。

- **游戏好友**：处理收到的申请、取消发出的申请、删除好友、邀请在线好友进当前房间。双方接受前不算好友。
- **最近见过**：记录真实同房的人。打招呼，或同一次在场期间双方都参与房内聊天，会记录互动时间；近 30 天互动显示「最近互动过」并优先显示。世界频道发言、历史消息和本地试演不算互动。
- **Steam 好友**：原有好友与邀请操作移动到此页签，仍由 Steam 连接提供。
- 离线仍能查看上次保存的联系人，状态显示未知。缓存角色可尝试「角色试演」，缺少素材时明确提示；不会向离线本人发送邀请。
- 房间成员旁直接加好友；收到申请时显示接受入口。朋友导航显示待处理申请与邀请数量。

服务端新增 `rooms/contacts.mjs`，和 `server.mjs` 一起发布。数据在服务端 `DATA_DIR/contacts.json`，临时写入后原子替换。玩家凭据只保存在主进程 `userData/room-contacts.json`，按服务 URL 隔离；备份存档时保留此文件。角色切换不改变玩家身份。

尚未做 Steam 登录票据服务端验证，所以不会凭客户端提供的 Steam ID 合并不同身份。遗留客户端只提交公开 ID 时，不能取得已保护身份；跨设备迁移目前需转移自己的本机存档，尚无账户找回页。

房间邀请仅向在线游戏好友发送，2 分钟有效，收到者明确选择接受后加入。删除关系、邀请人离房/断线、目标被踢、满房等情况会在接受时重新校验。好友关系与申请持久化，房间邀请不跨服务重启。

旧服务通过能力检查显示「尚未支持朋友列表」。本次没有部署公网服务器。`npm run dev:social` 可运行配套的本机服务，但此既有启动器使用临时数据和随机端口，不适合跨次保留测试好友；需要测试重启持久化时，使用固定 `HOST`、`PORT`、`DATA_DIR` 启动 `node rooms/server.mjs`，将客户端 `QBOT_ROOMS_URL` 指向该服务。

验证：`node scripts/test-friends-server.cjs`（真实多人关系、身份冒用、离线、服务重启）；`node scripts/test-social-ui.cjs`（原生窗口朋友页、最近互动标记、申请、邀请、Steam 页签和窄窗）。测试采用临时账号、存档和回环服务，不读取或修改真实好友。
