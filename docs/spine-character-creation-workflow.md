# Q 版 Spine 角色创建流程

2026-10-11 用户确认：完整 2D 目标图、接近现有骨架的比例、Grokbot 风格的完整表情行为，均为创建流程的必需部分。

**状态：已确认的创建规范。** 当前可执行的是人工辅助生图、拆图、模板装配与抽帧检查；自动锚点识别、自动修正闭环及完整动态表情尚未实现。本规范不能作为这些功能已上线的证据。适用于新建 Spine 人形角色；现有视频生成流程及已认可角色不自动迁移。

**佐助肩部实测补充：** 模板范围内已有 `auto-spine-shoulders.cjs` 自动袖根 alpha 定位、横向搭接和胸部／上臂过渡绑定，仍依赖经审阅的部件布局与肩线高度，不能代替通用语义锚点识别。接缝检查须先区分几何偏移与素材自带袖窿／重复描边：前者校准，后者局部重绘后重装，不能无限平移遮盖。佐助 GPT 版的肤色袖窿由人工识别并触发补图，自动质量判断与闭环仍待实现；具体复现与限制见 `spine-sasuke-gpt-trial.md`。

**人形适配修订（2026-10-11）：** 用户否定原表情板 04 Searching 和 11 Curious：有固定发型的人形不采用圆球式整体转动、脸部横移或夸张大小眼。两项作为历史标签保留但标记 `disabled_for_humanoid`，不出现在人形可播放表情列表；当前有效表情为 23 类。`searching`/`curious` 状态语义仍可保留，须另做适合人形的明确映射，不能借标签保留偷偷恢复被否定的视觉效果。下方 25 行为原始完整目录，禁用行不计入有效覆盖率。

鸣人实验预览已接独立实时眼形层与 23 个可点击标签，支持重播、开合、单眼眨眼、过渡、暂停和睡眠覆盖；头发/头部网格不由表情层变形，眼睛在校准位置原位变化。该试播不代表 39 状态映射或自动创建流程已上线。实现 `output/spine-lab/expressions.js`，检查 `scripts/test-spine-expressions.cjs`，入口 `http://127.0.0.1:24361/?skin=naruto`。

## 创建顺序与通过条件

| 阶段 | 必须产出 | 进入下一阶段的条件 |
|---|---|---|
| 1. 输入与模板 | 角色参考/描述、身份特征清单、骨架版本与实际中性站姿 | 确认二足人形可适配；特殊结构明确标出 |
| 2. 完整 2D 目标图 | 完整全身图、同尺度骨架站姿对照、比例记录 | 保留身份，比例接近模板；用户确认目标形象 |
| 3. 表情设计 | 25 类表情板、39 状态目录、状态→表情池→身体动作映射 | 表情有辨识度；标签完整；用户确认表情方向 |
| 4. 版本锁定 | 目标图、表情方案、模板的版本与哈希、确认记录 | 所有确认对应当前版本；不能默认继承旧图确认 |
| 5. 部件生成与检查 | 真实透明部件、脸部安全区与关节锚点、问题清单 | 不缺件、不截边、不重复袖子/手/脖子；保持锁定形象 |
| 6. 自动校准与装配 | 独立校准参数、Spine JSON/atlas/PNG、指标与修正记录 | 在模板约束内求解；低可信度或不可修正缺陷明确停止 |
| 7. 动态与表情验收 | 目标图/静态装配/动态对比，动作抽帧，完整表情及状态覆盖报告 | 数值、视觉、标签覆盖分别检查；未支持项目明确列出 |
| 8. 创建完成 | 可预览角色包、能力清单、已知限制、版本与来源 | 核心验收通过；未完成必需能力时仅标记试作，不称全套完成 |

形象与表情可以同页一起确认，无需机械地拆成两次提问。用户已确认且素材未改时直接继续，不重复索要确认。安装、激活和发布沿用原创建流程的显式操作。

## 目标原画必须受骨架约束

- 先从选定模板实际渲染中性站姿，再生成目标图。不能先画任意比例，最后通过强拉伸凑进模板。
- 比较发顶、下巴、肩、髋、脚底位置，以及头高/全高、头宽/躯干宽、肩宽与腿长。记录归一化坐标、测量口径和容差；当前尚未验证通用数值容差，不宣称机器已经判定合格。
- 头部等比缩放；脸、发型和配饰轻微朝画面左侧，与当前模板一致。明显超出模板能力时调整目标图或选择模板，不牺牲角色身份。
- 鸣人参考实测：发顶至中央下巴约占全高 64.3%，含发型/绑带的头部轮廓宽约为躯干宽的 3.30 倍。这是当前鸣人换皮的参考值，不是所有角色的硬编码常数。
- 本轮认可的方向参考：[鸣人目标图](../output/spine-lab/naruto-target-v4-rig.png)、[表情板](../output/spine-lab/naruto-expression-study-25.png)。方向认可不等于像素级对齐或最终动作验收；目标图仍需校准，部分静态眼形仍需区分。

## 表情是独立的可动层

默认采用无高光、纯深色胶囊眼及其形变，保留角色自身的头发、脸型、肤色、胡须纹和配饰。眼睛不烘焙在头部底图上。默认不固定笑嘴、不加鼻子，以免开心嘴与生气/难过眼冲突；若角色确需嘴部，作为独立可动附件并随表情变化。

必须覆盖眼形轮廓、开合度、左右不对称、限幅视线、自然眨眼、单眼眨眼及平滑弹性过渡。状态控制表情池、停留节奏和允许的头部微动，不能把每个状态实现成同一张脸。头部微动须与 Spine 动作叠加受限，避免双重位移和关节脱开。

区分三层数据：

1. **表情**：双眼具体形状及变化参数。
2. **状态**：情绪或任务语义，决定表情池、视线、节奏和附加效果。
3. **身体动作**：Spine 动画名称及已有 QBot 语义动作映射。

三层分别保留稳定 ID、中文显示名和支持状态；不能拿源骨架 178 个动画代替表情覆盖率。现有 22 个桌宠动作和六类运行时表情保持兼容，新目录通过显式映射接入，旧标签不静默删除或改义。

以下是本项目的设计标签，不宣称对应第三方 `expression00`–`expression24` 的原始顺序。表情板为候选形状，运行时需绘制可插值的独立眼形，不直接把整张头部表情图当动画帧。

| thinking | 思考 | 不对称开合，短暂停顿与侧视 |
| searching | 寻找（原 04，禁用） | 不采用圆球式移眼；保留历史 ID，不提供人形试播 |
| focused | 集中 | 收窄，降低游移 |
| happy | 开心 | 上弯笑眼 |
| excited | 兴奋 | 更大开合，较快反应 |
| laughing | 大笑 | 紧闭笑眼，节奏更强 |
| proud | 得意 | 放松的半睁与不对称 |
| shy | 害羞 | 眼形缩小、视线回避 |
| curious | 好奇（原 11，禁用） | 不采用夸张大小眼；保留历史 ID，不提供人形试播 |
| confused | 困惑 | 不对称倾斜，短暂停顿 |
| suspicious | 怀疑 | 窄眼与侧视 |

### 39 个状态标签

保留研究参考中的语义 ID，不把任务效果伪装为眼形。每个状态需分别记录 `expressionPool`、`bodyAction`、`gaze`、`blink`、`transition` 与 `effects` 的映射/支持状态。这里的字段是拟定数据契约，不表示当前 manifest 已支持。

- 基础（7）：`idle` 待机、`sleeping` 睡眠、`waking` 醒来、`listening` 倾听、`thinking` 思考、`searching` 搜索、`working` 工作。
- 情绪（16）：`excited` 兴奋、`surprised` 惊讶、`suspicious` 怀疑、`angry` 生气、`drowsy` 困倦、`happy` 开心、`curious` 好奇、`confused` 困惑、`bored` 无聊、`proud` 得意、`shy` 害羞、`sad` 难过、`laughing` 大笑、`scared` 害怕、`playful` 调皮、`celebrate` 庆祝。
- 任务形变（3）：`orbit` 轨道、`radar` 雷达、`progress` 进度。
- 任务周期（13）：`spawning` 生成、`humming` 运转、`loading` 加载、`dictating` 听写、`writing` 书写、`sending` 发送、`receiving` 接收、`uploading` 上传、`notifying` 通知、`alerting` 警报、`dragging` 拖拽、`bouncing` 弹跳、`powering-down` 关机。

未实现的形变/粒子效果保留 ID 并标 `unsupported`，可以有显式记录的安全回退，但不能标成已实现。外形无需变成 Grokbot 的几何球体；人形角色优先保留身份，任务效果采用适配方案。只有标签存在不构成完整支持。

## 自动校准与返工

### 已认可的颈肩与双臂经验（2026-10-11）

用户已认可鸣人、张起灵和吴邪的最新颈肩/手臂修订；这些是回归样例，不代表通用自动求解已完成。

- 待机双肩一起验收。分离头、躯干、左右袖，明确是衣身高肩还是袖根顶头；不能只改被指出的一侧。固定姿势记录两侧袖顶及肩关节位置，并扣除原骨架姿态/透视造成的合理差。
- 鸣人 v6→v7 同一 1100×500 隔离手臂渲染中，alpha>128 的两侧袖顶差从 16 px 降为 1 px。该结果仅为样例，不可硬编码成任意尺寸、任意动作的阈值。
- 当前大头模板默认采用“视觉隐藏颈部”的头肩连接，**不要求可见脖子**。保留原有头颈控制骨与动画，头和眼嘴整体调整；禁止将视觉无颈误解成删除颈骨。衣领是服装识别特征，不得为了表现高领画出一段竖直柱体。可见短颈作为角色适配例外，经同姿势目标图与装配对照后选用。鸣人 body_3 缩短 4 单位仅是历史样例，不是生成规范。
- 目标图先明确下巴、衣领下沿和两侧袖顶：中央衣领藏入下巴遮挡区或仅露薄边；肩线向两侧自然下降，袖根从衣身侧面接出，不能靠提高肩膀去填头身空隙。禁止强制所有角色统一领高／肩高。佐助 v4 的衣领压缩和肩部下放是待用户视觉确认的实现样例。
- 衣身和袖子分别校准：保留中间衣领搭接，降低过高衣身肩顶；袖根接在躯干侧面，腕端和肘部保持连续。缩短夹克不等于修复肩部。
- 两侧袖根应适量伸入衣身遮挡区，由躯干盖住连接边；不得只与衣身外轮廓相切。必要时拆分袖帽与前臂的绘制层，袖帽在躯干后、前臂按动作保留前景，不能把整条手臂藏入身后。内收幅度向肘腕衰减，并检查抬手的搭接；佐助 v5 的 9 单位只作实验参数。
- 生成提示词同步采用无独立颈段、低而薄的领部、自然下落肩线；头块不带脖子／衣领，躯干提供被下巴遮挡的搭接区，不画露肤袖窿。试图通过压缩、抬升或遮挡修复仍无法达到目标轮廓时，返回目标／部件重画，不以自动校准得分宣告成功。
- 透明区域外扩后，原模板三角网格可能折叠。使用经过验证的躯干/袖子规则拓扑；袖子按实际肘部混合上下臂权重。新增角色不直接套用原有不匹配三角网格。
- 顺序固定为：部件打包 → 网格校准 → 动作渲染。打包会覆盖骨骼 JSON；校准必须从原模板计算，重复运行不得累积位移。
- 同姿势、同尺度输出原角色/修改前/修改后对照；七动作四分位必须包含待机、抬臂、弯肘、跑步、睡觉。数值无异常不能代替视觉验收，保留仍存在的下摆或道具限制。

样例工具：`scripts/calibrate-naruto-mesh.cjs`、`scripts/calibrate-spine-sleeves.cjs`。正式创建入口设计及成本口径见 [Spine 创建类型设计](superpowers/specs/2026-10-11-spine-creation-type-design.md)；该新入口尚未实现。

按[自动校准设计](superpowers/specs/2026-10-11-spine-auto-calibration-design.md)执行：视觉识别锚点，确定性程序映射到模板，生成独立校准参数；最多三轮装配/检查（初次及两次修正），保留最佳有效候选。

五官和接缝偏移可自动修正；重复肢体、错误方向、素材缺失和明显网格不适配应回到部件阶段。无改善、低可信度或达到上限时报告未解决问题，禁止将“流程结束”当成“质量通过”。不能把上一角色的坐标当作本角色已校准结果。

## 验收清单

- 目标原画、静态装配和动态结果同尺度对照，身份和比例不得明显漂移。
- 七类身体动作各四分位：待机、走路、跑步、开心、侧躺睡觉、喝茶姿势、贴贴；放大检查颈肩、肘腕、髋膝踝和衣摆。
- 当前 23 类有效人形表情逐项有中性头姿的动态预览，检查眼形可辨、位置不越界、不重复眼睛、不露旧鼻/嘴；原 04/11 必须不可播放。不能只检查静态表情板。
- 39 状态逐项有实际映射和支持报告；状态数、表情数、身体动作数分别统计。
- 检查全部已支持状态的有序切换，包括自身重入；睡眠不随机睁眼，醒来/眨眼/单眼眨眼能恢复双眼；快速切换不残留旧表情。
- 覆盖左右视线、镜像、头部微动、开心/睡眠身体动作，以及暂停/隐藏恢复、减少动态效果设置。
- 骨骼矩阵有限值、图片可加载、标签存在，都不能替代视觉通过。喝茶道具、双人编排、长发/裙摆等未覆盖能力单独报告。

## 四肢自查补充（2026-10-11）

禁止用有限数值或站姿好看来代替动态验收。采用肩肘腕／髋膝踝定位，肢段分别绑定，关节附近窄带混合；检查反拐、拉伸、锚点偏离和截面塌缩。七动作各八帧并保留视觉复核，旧装配批准不得继承给新装配。完整门槛见 `superpowers/specs/2026-10-11-spine-self-check-design.md`，小樱实验及仍需人工的部分见 `spine-sakura-self-check-trial.md`。
