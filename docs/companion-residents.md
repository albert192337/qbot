# 世界陪伴角色模块

日期：2026-09-25。先记录设计，再实施。目标是让冷启动世界里有人可拜访、可聊天、可一起玩，并作为正式上线后的可运营模块保留。

## 体验

- 六名常住伙伴、三个主题房间：花园茶会、安静自习、晚风闲聊。昵称、稳定账号 ID、装扮、在线姿态、种植品种、进度和角色经验各不相同。身份为「陪伴角色」，不冒充真人账号。
- 素材仅从装扮市场读取已经完成的角色包，复用现有下载与动作播放器。按稳定排序绑定不同市场角色，绑定结果持久化；缺包不生成空白角色，也不触发付费生成。
- 玩家进房后稍等再欢迎；房友之间轮流聊天，聊天有主题和回应关系。玩家发言后延迟接话；忙碌/自习时减少主动说话，不逐条复读玩家输入。
- 体验自测后：连续短消息以最新一句回复；玩家发言会取消排队的无关闲聊。说「想安静一会儿」后停止主动闲聊与邀请，再次主动聊天恢复；邀请直接显示在聊天小窗内，不必跳到朋友页。
- 停留一段时间后，空闲伙伴可主动发出喝茶、打招呼或小心心邀请；玩家明确接受才表演。拒绝、忽略或退房后不追问。同一玩家最多每半小时一次主动邀请，跨重启保留。
- 花园使用现有权威规则和公开视图，不在客户端伪造资产；不同伙伴有空地、幼苗、生长中、成熟留田的组合。初始化只发生一次，不因重启重置或重复发奖励。小店保持账号差异和既有购买上限。
- 每名伙伴错峰照料花园，之后每 12–23 分钟采一块、出售一份、按已有种子或商店库存补种；第一块作为留念。全部走普通种植/采收/购买规则，资源不够就停，不凭空反复补资产；彩色待揭晓果不会跳过培育。

## 实现边界

`rooms/companions.mjs` 封装名单、素材校验、持久绑定、时间调度、对话脚本与花园初始化。服务端适配器接入现有房间广播、世界消息、花园与邀请管线；不创建假 WebSocket 网络连接、不混入真实连接统计。客户端只补充陪伴身份标记。

服务配置 `QBOT_COMPANIONS=1` 才开启；`QBOT_COMPANION_MARKET_DIR` 指向市场 data 目录。角色包以 SHA256 和包内 manifest 校验后进入现有缓存，模块不读取私人角色人设。关闭模块不影响真人房间；伴随房间不进入普通房间存档，重新启用仍沿用账号和花园。`companions.json` 保存绑定和邀请冷却，不保存玩家聊天正文。

世界广播在有人订阅时才定期发送；房间对白仅有真人在场时运行。消息走原有 50 条上限，不补造历史时间戳。每房最多两名陪伴角色，给真人留足容量。真人发送消息优先，主动对白避让。无模型调用，使用小型主题对话与关键词回应，未知内容不假装理解。

双人互动复用原有等级、同房、超时、忙碌检查。假人收到玩家邀请后延迟接受，收到主动邀请的玩家仍可拒绝。花园与互动记录按陪伴账号存储，不允许客户端用公开 ID 登录这些账号。

## 验收与上线

### 2026-09-25 联机双人互动修正

联机双人表演同一成员只能有一个展示位置：开始播放前由主进程暂时隐藏原房友窗（含名牌和提示），结束、打断或本机窗口重载/关闭后恢复；临时隐藏不写入玩家的手动隐藏设置，并阻止窗口晚加载或全局显示时重新冒出。联机表演不创建转向、换边、结束等试演工具栏，保留自然结束和拖动打断；本地试演仍保留调试工具栏。

邀请在自己角色外侧的独立提示窗显示「一起玩／暂时不了」，优先上方，无空间时侧边或下方；移除聊天页邀请卡。沿用 interaction 60 级仲裁，隐藏、窥探、双人表演时不抢占；过期收起，按邀请 ID 防止旧按钮提交，失败可重试。

八种联机互动统一接入本地双人导演：自己的角色与房友缓存素材同时播放，按发起／接受身份分配动作与效果方向，完整片段后进入下一段。现有服务首段双方意图各不相同，可兼容线上协议，无须升级服务。后续网络分段不重启双人动画，离房、对方离场、隐藏、切角、拖动和结束沿用清理。素材尚未就绪时仍使用单人兼容动作。

验收入口：`app/test/garden-network-interaction.test.ts`、`scripts/test-pair-interaction.cjs`（实际双播放器）、`scripts/test-pair-invitation.cjs`（生产外侧窗口、按钮与生命周期）。本次修正需要加载新版客户端；服务器已有陪伴角色并不意味着正在运行的旧客户端会自动更新。

用临时目录和市场 fixture 测试：稳定身份/不同角色、非法包拒绝、花园差异和重启保留、延迟欢迎/对话/回复、邀请冷却、离房取消、玩家接受与拒绝、关闭模块，以及真实 WebSocket 的列表/进房/素材下载/花园互访链路。回归既有社交与花园服务。

本轮开发与本机验证，不自动重启运行中的客户端或部署公网。上线时将模块与新版 rooms 一并部署，配置市场目录与开关；先在独立数据目录验收，再启用正式实例。后续可扩展节假日话题、运营名单和更丰富的对话，首版不承诺自由生成式聊天或全天在线调度。

## 配置与验证命令

本机手动试玩：在仓库根目录运行 `node scripts/play-companions.cjs`。它打开独立「一起玩」测试窗口并进入世界广场，不自动发送测试聊天。点任意陪伴房间的「拜访」，再开聊天小窗。关闭一起玩主窗口退出，并清理临时存档。本机市场缓存复用 `output/companion-review/market`，首次运行读取公开市场素材；需要已构建的 App 与 Playwright（可通过 `PLAYWRIGHT_MODULE` 指定）。

房间服务启动环境中设置 `QBOT_COMPANIONS=1` 和 `QBOT_COMPANION_MARKET_DIR=<市场 data 的绝对路径>`，后者目录结构为 `<hash>/pack.bin`。无需市场管理码。模块读取素材，不改市场文件；六份有效素材时可绑定六个不同角色，素材较少时允许复用。已绑定素材丢失则该角色暂不上线，不偷偷换装。名单和花园保存在房间服务 `DATA_DIR` 中。

从仓库根目录运行：

```text
node --test --test-isolation=none rooms/companions.test.mjs
node scripts/test-companions-server.mjs
node scripts/test-social-server.cjs
node node_modules/typescript/bin/tsc --noEmit -p app
```

实测通过：四组规则测试、真实回环 WebSocket 的三房六角色/素材下载/花园互访/延迟对话/世界消息/接受玩家邀请/主动邀请与玩家拒绝，原有社交回归和类型检查。素材测试使用市场格式的最小 fixture，只验证分发与协议，不等同真实市场视频的桌面播放和长期挂机验收。客户端身份标记已加入成员、消息和朋友列表。

后续真实体验自测已补充：五组模块回归，以及六份实际市场素材、两名访客的实际视频播放、聊天小窗接受邀请、65 秒安静观察。详细结果与仍存在的脚本感见 `docs/companion-experience-review.md`。
