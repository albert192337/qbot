# 表情包角色：原样生成与独立封面

表情包创建默认 `generationMode: original`。旧表情包任务在读取时采用同一模式，保留旧任务 ID、付费视频 ID 和已生成文件。不自动补三视图，不默认人形；基础动作、预设和自定义动作沿用原线条、颜色、身体结构和比例。用户明确保存的完整 prompt 覆盖仍优先。

## 使用

- 角色资料 → 选择封面：可选原始参考图、已选三视图左侧第一幅，或任一可用动作的指定秒数。保存为独立 `cover.png`，选择记录在 `.cover.json`，不改 `source.png`。
- 表情包基础动作 → 重新生成：选择本次参考帧 → 确认生图费用 → 对照原图检查生成首帧 → 确认后生成视频。取消后保留首帧，再次打开可继续，不重复生图。原动作直到新视频完成后才合并。
- 市场包没有原 GIF 时从已有透明 WebM 取帧；超出片长报错，不偷偷回退第一帧。
- 原样模式不强迫站立、摆双腿或加粗描边。待机保留参考姿态；拖拽按原结构整体轻微悬浮摇晃。

## 数据边界

封面只用于本地展示及市场预览。市场仅上传明确选择的 `cover.png`，不再自动上传 `source.png` 当封面。下载预览保存为 `cover.png`，不覆盖包内参考图。封面和本地选择记录不进入角色资产包，也不用于模型输入、桌宠播放兜底或旅行视觉参考。

历史市场下载曾覆盖的 `source.png` 不会自动修复，也不猜测正确姿态；下次生成可直接从原表情动作另选参考帧。已有动作不会自动重新生成或花费模型费用。

每次基础动作生成保存独立 `.job/<action>_reference_<uuid>.png`，任务记录来源动作、秒数及待确认标志；`<action>_request.json` 保存实际参考路径及首帧、视频提示词，不记录密钥。视频只在已确认首帧后提交，恢复任务不会跳过确认，确认时校验画面未被替换。

两步首帧确认目前用于表情包的基础动作重新生成；既有自定义/预设动作仍沿用原有生成流程，已经接入原样提示词。云端普通角色任务保留原流程。

## 验证

- `npm test -w pipeline`：原样动作约束、选择参考图、首帧确认/重启与付费任务恢复；真实 FFmpeg 取帧、转码。
- `npm test -w app`：封面隔离、市场下载不覆盖参考图、无封面不发布参考图、旧任务保留及资产包边界。
- `npm run build -w app` 与 `npx tsc --noEmit -p app`。
- `scripts/test-character-images.cjs`：隔离 Electron userData，真实界面与 preload，模拟模型调用且禁网；选择封面、指定时间、取消/恢复首帧确认及不重复生成。截图在 `.superpowers/character-images/`。

没有进行付费生成；提示词与流程校验不代表真实模型相似度已经验收。
