# Spine 通用 Q 版骨骼换皮试验

2026-09-26。本地样例已经完成：AI 生成六块新部件，机械对齐到原图集区域，复用原骨骼、网格权重、变形时间线和表情。未接入正式客户端。

## 已确认规范与吴邪样例

## 第二轮：截图角色与独立豆豆眼

视角适配：用户指出原骨骼轻微朝画面左侧，新正面头部与它不协调。新增 `hood-head-left.png`，通过 imagegen 重画兜帽、刘海、脸颊和耳朵为浅三分之四左向视角；右侧近耳可见、左侧远耳收起，小黄鸡同步微侧。装图仍保持长宽比；五官轴向左移动，远侧眼略窄，闭眼同位置校准。身体、原骨骼和此前贴贴膝盖适配保留。原正面版本截图/图集保存在 `hood-front-view*`；默认预览为微侧面。

贴贴腿部适配：完整周期检查发现原 `town_shuangren_tietie01` 后半段胯与脚横移、独立 knee target 近乎停留原处，短裤原皮也会产生夸张折弯，长裤更明显。新兜帽皮肤仅此动作在动画求值后将膝目标约束到髋脚线段 35%–65% 范围、侧向偏移不超过 4 个骨骼单位，再计算 IK。保留上半身、髋脚原动作，不改源 JSON。每帧先还原 knee 局部基础坐标，避免修正累积。`scripts/inspect-spine-together.cjs` 复查全周期九张图与连续 600 帧，验证最大横向偏移 4、逐帧/直接跳转一致、返回 idle 无残留；`together-validation.json` 保存结果。原始左侧角色不做该修正。预览支持 `?skin=hood&action=town_shuangren_tietie01`。

第三次面部校准：用户对照截图指出五官拼装不协调。确认之前直接继承原面部坐标导致整体偏左、嘴偏低，胶囊眼丢失原图斜上沿；头部按旧猫帽边界非等比缩放又使脸变宽。新增 `hood-face-parts.png`（imagegen 按截图重画的左右斜上沿短眼及短嘴），按新脸中心重新定位、缩短眼睛、抬高嘴、调整眼距，闭眼同步校准；头部装图改为等比缩放居中。`face-alignment-comparison.png` 是截图参考/修改前/校准后对照。并非像素级复刻原画，头发和身体依然是生成版本。

用户指出第一版仍保留猫耳帽和相似发型，要求按截图重做。默认预览现为小黄鸡兜帽少年：黑色碎发、圆形深蓝兜帽、小黄鸡、蓝外套、黑色长裤、手套和红腕绳。`hood-reference.png` 保存用户截图，`hood-parts.png` 是按该截图生成的九部件透明图；`hood-atlas.png`、`hood.atlas`、`hood.json` 为实际播放资源。旧银发版本通过 `?skin=traveler` 保留。

这次六块身体贴图及双眼和短线嘴全部替换。豆豆眼与嘴分别复用原面部网格的 UV/位置；新增两块闭眼贴图由生成的短线素材机械缩放装入。运行时关闭旧表情附件，保留新双眼和短嘴，提供定时眨眼与睡觉闭眼；因此开心等动作目前保留身体动作、面部仍是截图的中性风格，并未逐一重制 178 套表情。小黄鸡和兜帽同属头部贴图，尚无独立骨骼。

`scripts/spine-lab-hood.py` 按透明间隔检测三行三列，而非假定模型会严格遵守指定尺寸。首版按等格切分发现下巴、手脚被切掉，现已修正并目视复核待机、走路、侧躺睡觉与贴贴姿势。178 动作数值复核加上新眼睛可见、旧大眼/红鼻不回流及睡眠闭眼检查。此轮仍使用原骨骼头身比，尚非截图比例的像素级复刻。

## 启动与复核

在仓库根目录运行 `node scripts/preview-spine-lab.cjs`，打开 `http://127.0.0.1:24361`。

`node scripts/check-spine-lab.cjs` 在隔离 Electron 中检查 178 动作各五个时间点的骨骼矩阵是否有限值，保存待机、走路、开心、睡觉、喝茶姿势、贴贴单方动作截图，并检查动作切换和骨骼开关。加 `--frames` 可输出四个动作共 8 秒的 24 FPS 确定性对比帧。隔离 profile 在输出目录内，不使用正式 QBot 存档。

已检查的六组截图能显示新皮肤并跟随动作，待机/走路/开心/侧躺睡觉可作为概念验证。178 动作的数值检查全部通过、无页面异常；这不等于 178 个动作全部视觉合格。喝茶只有人物姿势，本包没有对应场景茶杯与座椅；贴贴目前是两边各播同一动作的对照，尚非两人配对编排。原骨骼某些表情会叠眼、睡觉眉毛在帽子上，新皮肤还存在刘海与眼眉层级问题，需要单独整理面部附件。

## 得到的结论

“按模板生成新 Q 版部件 → 套既有加权网格 → 复用动作”已被本次样例验证。这样新增角色时可以只生成一套图，动作由本地渲染完成。它与 Spine 官方的 [Runtime Skins](https://eu.esotericsoftware.com/spine-runtime-skins) / [Mix and Match](https://eu.esotericsoftware.com/spine-examples-mix-and-match) 机制一致。

这次没有验证“任意外部原画 → 保持身份特征的 Q 版 → 全自动拆图”的完整链路；新人物由模板直接生成。下一步应选一张真正不同的人物参考，让模型按模板保留发型、服装、配饰特征，并检测脸部关键点、肩肘腕及髋膝踝位置。只按不透明边界缩放的办法适合这个相近轮廓样例，不能视为通用自动绑定。

建议先支持二足、近似比例的 Q 版人形，明确统一头身比、正面/轻微侧向、关节坐标、脸部留白、分层顺序和遮挡补全规范。长发、裙摆、大袖、尾巴、持物需要扩充附件与校准；四足、无定形、明显不同体型需要其他骨架。复杂动作应做接缝和遮挡回归，并筛选可用动作集。

QBot 现有 Player 播放透明 WebM/GIF。低改动集成可以先把骨骼动画离线导出透明视频复用现有播放器；实时 Spine 播放则需要新增播放器和角色包格式、资源打包与联机兼容。此轮未选择或接入任一路线。
