# 3D 房间正式接入

默认入口是控制台的「装扮房间」。3D 和 2D 都在这里编辑，按钮会记住选择；未设置过时使用 3D。

## 保存与桌面

3D 的家具布局、相机位置、目标点、视图和侧墙状态保存到用户目录 room3d.json。保存时验证长度、数值和重复键，串行原子写入；已打开的桌面房间实时更新。旧 2D 存档和库存仍沿用 room-decor.json，两套资产分别保留。

编辑器的两位客人用于预览。正式桌面取当前激活的角色和 rooms.getSceneMembers 提供的实际房友，订阅角色激活、房友状态、成员隐藏、Agent 状态和行为动作；不会把两个预置角色当作当前玩家。切换素材释放旧播放器、纹理和阴影。

主进程 openRoomWindow 根据 roomRenderMode 选择 tea3d?desktop=1&live=1 或 online-room。启动激活角色、切换角色及回到桌面默认打开房间。既有宠物窗口保留作为行为执行来源，房间显示时隐藏；房间由原有显隐管理统一控制。

控制台通过同源 iframe 承载编辑器并提供现有预加载 API，离开页面或切到 2D 时暂停 3D 播放。保存状态通过主进程 IPC 传递。独立样板仍使用自己的本地存储，不写正式存档。

## 验证

- 类型检查、完整应用构建。
- scripts/test-room3d-integration.cjs：真实内嵌编辑器、默认 3D、保存磁盘与桌面联动、视频/Spine 激活切换、房友加入/隐藏/恢复、2D/3D 保留存档、重开、无效保存拒绝。
- scripts/test-tea3d.cjs：家具拖动、替换、座位、动画、相机范围、桌面锁定和侧墙切换的现有回归。

当前模型库仍是听雨茶室的八件 3D 家具；2D 主题素材没有自动转成 3D。楼层按钮的上层仍是陈设示例，布置不跨玩家同步。

正式客户端已正常重启并实机确认：自动打开 3D 房间，当前角色动画 ready；控制台装扮页默认选中 3D，内嵌页面和预加载桥接 ready。600 像素桌面工具条保持横排。结果与截图在 output/room3d-official/；类型检查、完整构建、正式联动及原茶室交互回归通过。
