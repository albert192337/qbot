## 分工与资产拆分（建议）

| 层 | 制作方法 | 运行时行为 |
| --- | --- | --- |
| 果实、果萼/叶冠 | 设计图 → Tripo → Blender 清理，分对象或材质区域 | 分区域换材质、体型变化 |
| 泥土和植株叶子 | 独立底座模型，低矮中央留空 | 种植时显示、收获展示不带土 |
| 茶壶、蝴蝶结、花饰等实体挂饰 | 各自设计图 → Tripo 独立生成 → Blender 精修 | 使用相对果实尺寸的挂点，漂浮/摆动 |
| 玉润、珠光、晶透、金属、星河 | Blender 确认目标，应用内材质/着色器实现 | 同一基础模型复用，必要时纹理遮罩 |
| 音符、光环、星点、雨丝、拖尾 | 设计过的透明纹理、少量几何与程序动画 | 可配置强度与动态效果降级 |
| 绒毛等改变轮廓的效果 | 专门设计的外壳/毛簇/材质组合 | 单独性能验证，不能仅靠粗糙度解决 |

Tripo 负责实体形状和基础贴图，不能把截图里的光晕、透明感与动画一并可靠生成。程序继续负责组合、材质和动效，不再把粗糙原型几何当作最终精致挂饰。简单形状可直接 Blender 建模，不必每件都生成。

## 制作顺序（建议）

1. 先做一套完整样板：普通草莓、一个晶透/星河变体、一个精致茶壶挂饰、一组克制音符/星点；先验证一个挂饰，再测试两个挂饰组合。
2. 普通果实与挂饰分别确定设计图。实体参考不带光效、字样和环境；透明/发光效果另附目标图，避免生成到网格中。
3. Tripo Studio 逐件生成，优先智能网格；走现有 DCC Bridge 导入 Blender。API 不是必需路径。生成一次基础形状，不为每种颜色/词条重复付费生成完整果实。
4. Blender 检查背面、底面、薄叶、破洞、UV 和纹理；分离果实与叶冠，统一朝向、原点和尺寸，为挂饰设置顶部/侧面位置。移除隐藏碎片，简化但保护轮廓。
5. 导出 GLB，应用内统一灯光与材质，再做光效和动画。Blender 与应用渲染效果不保证相同，必须在真实应用画面验收。
6. 词条工坊作为验收台：大模型可旋转，右侧分基本信息和槽位；选择时能清楚看到对应区域变化。正式详情页仅显示实际词条，不把试验选择器变成玩家改词条功能。
7. 草莓样板达到目标后再扩展菠萝、其他挂饰和正式展示入口。当前步骤仅文档设计，不替换正式资产。

## 初始预算与验收

- 以下是项目建议起点，不是 Tripo 能力限制：果实含叶冠约 5k–10k 三角面，底座 2k–5k，单挂饰 1k–5k；以导出后三角面为口径，四边面可能拆为两三角面。必要时为复杂轮廓增加预算。
- 果实贴图先 1K、挂饰 512–1K；若 Studio 最低提供 2K，离线缩小后视觉比较。不要再默认 4K/8K 或几十万面。
- 普通手绘款可先简化 PBR；金属茶壶等需要受控金属度/粗糙度。开 Tripo PBR 不等于自动获得参考效果，晶透/星河需要应用内独立实现。
- 真实透明桌面里折射不能默认读到桌面壁纸；透明材质需设计可接受的环境反射/渐变替代效果。
- 验收实际小尺寸和放大详情、正侧背面、浅深背景、旋转中遮挡、双挂饰冲突、多个果实同屏、减少动态效果。镜头取景包含挂饰，避免切顶。
- 品质色与视觉词条分开，遵守已有品质规则；不为匹配参考擅自更改经济、抽取或槽位规则。
