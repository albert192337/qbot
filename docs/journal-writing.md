# 人设手账与今日朋友圈

## 使用

- 开启 LLM 模式并配置 Ark Key 后，真实旅行会在保存体验后异步写手账。打开旅行手账也会补写当前角色未生成的记录；卡片的「按人设重写」可重试或使用新提示词。
- 任意城市的测试重玩也支持人设文案。模拟进度只用于本次手账，不进入真实旅行存档、朋友圈上下文或共同记忆。
- 「测试：写今日朋友圈」每次成功生成一条独立本地卡片，支持点赞并在重启后保留。按钮显示生成状态；失败不添加占位文案，可重试。没有任何旅行记录也可生成。它不向外部社交服务发布。
- 工具抽屉 → 开发者工具 → 手账与朋友圈提示词，可分别保存、清空或恢复默认。修改在下一次生成时生效，既有文章不会自动替换；旅行卡片可手动重写。

## 默认写作方向

旅行手账以角色第一人称记下一两件真实游戏体验，80～160 字，让人设体现在关注点和语气里，表达因为一起经历而珍惜的小心情。

今日朋友圈 100～220 字，从当天有记录的聊天、互动或花园小事写起，让用户感觉自己的话被记住、日常被放在心上。关心和爱意应符合角色及用户偏好，不强行恋爱化，不索取回应、不说教，不凭空断言用户疲倦或孤独。材料不足时写自己的陪伴心愿，不编造今天的故事。

默认模板：`app/src/shared/journal-prompts.ts`。两项设置全局共用，生成时填入当前角色名字和人设。角色／事实放在数据消息中，不作为新的操作指令。

## 历史范围与存储

- 当前角色今天仍保留的近期聊天最多取 30 条；现有聊天缓冲本身最多 40 条，不代表完整全天聊天档案。助手旧发言标为生成内容，不作为用户事实。
- 从当天原始交互记录聚合点击、拖动等数量，不传应用标题、路径或完整事件流。旧互动不含角色身份，因此不能冒充当前角色的独有经历。
- 共同收获及明确偏好遵守记忆的角色、有效性和不主动提及开关；只把当天事实当作今日经历。
- 普通播种、收获、出售和施肥从本次版本开始保存摘要到 `garden-demo.json/state.journalEvents`，保留 7 天、最多 300 条。旧日常操作不会回填。当前土地和库存只作为现状，不能称作当天的全部收获。
- 旅行日记按角色、日期、城市匹配；旧无城市字段的日记保留，可从已付费体验重新生成。朋友圈独立存于 `state.travel.moments`，不会消耗金币或推进旅行。

## 并发与失败

模型运行不占用花园事务队列，完成后合并最新存档。关闭 LLM、角色切换、记忆纠正或对应提示词改变会使旧请求失效。手账写回核对体验签名；朋友圈使用请求 ID 防止同一请求重复落盘，生成中拒绝额外点击。旅行写作失败保留事实文案，朋友圈失败不伪造内容。

- `app/test/journal-service.test.ts`：开关、角色和日期边界、自定义提示词、失败与重试、并发、幂等、过期结果、真实／测试手账隔离。
- `app/test/travel-memory.test.ts`、`travel.test.ts`、`garden-service.test.ts`、`garden-rules.test.ts`：手账写作、付费进度和普通花园记录。
- 先构建 App，再用 Electron 运行 `scripts/test-journal.cjs` 和 `scripts/test-travel.cjs`。临时用户目录、模拟模型、屏蔽 HTTP(S)；覆盖原生按钮、卡片与点赞、重载、错误与重试、小窗口和提示词保存／恢复。截图在 `.superpowers/journal`。

上述测试没有调用真实模型，生成文风仍需用户按角色实际体验后调节提示词。
